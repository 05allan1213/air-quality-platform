# Frontend instructions — City Air Quality Platform

## Scope and design discovery

- For work in `frontend/`, read the repository [AGENTS.md](../AGENTS.md) and the adjacent [DESIGN.md](DESIGN.md) first. DESIGN.md is the sole visual and interaction specification. Follow confirmed decisions, implement and verify requirements, and interpret measurements within their recorded scope. Implement, test and adjust candidate values and page layouts autonomously. Seek the user's decision for material changes to visual direction, brand identity, information architecture, interaction patterns or product scope.
- This directory starts with documentation. `prototypes/frontend-preview/` provides a local F homepage reference. Reuse a pattern only after checking its semantics, dependencies, asset rights and rendered behavior. Treat unverified page compositions as candidates within the confirmed navigation and module responsibilities.

## Implementation boundaries

- Use Vue 3, TypeScript, Vite, Vue Router, Pinia, Axios, Element Plus and ECharts. Once the formal app exists, follow its manifest and lockfile. Check installed versions and scripts before choosing commands. Use the existing stack for motion and controls. A new framework or large dependency needs a concrete unmet need and a scope decision.
- Keep page composition separate from shared controls, chart hosts and the same-origin API client. Put shareable, non-sensitive navigation conditions in the route, transient hover/focus in the component, and coordinated selection/session state in the appropriate shared owner. Use stable server IDs including site epochs where applicable. Preserve authorized filters and return context without retaining protected readings across sessions.
- Implement semantic values in one theme. Map Element Plus variables, chart options and the top-level overlay host to it. Scope component variants by name. Use the public mounting options available on each locked component. For nested overlays follow DESIGN.md §5, including accessible-tree and keyboard checks inside a dialog.
- Initialize ECharts once per visible, sized host. Observe container resizes, update series with stable IDs, and preserve valid zoom, legend and selection state. On unmount disconnect observers, release handlers and dispose the instance. Share a chart theme and provide an accessible data/keyboard alternative. Package permitted fonts, icons, locale and geographic assets locally with the relevant licenses and attribution for offline delivery.
- Use [v1 examples](../docs/api/v1.md) and the [frozen OpenAPI](../docs/api/openapi.v1.json) for fields, errors and permissions. Bootstrap CSRF with `GET /api/v1/auth/csrf/`, send `X-CSRFToken` for protected POSTs and all writes including login, then fetch a fresh token after login. Use the same-origin HttpOnly session cookie. Handle `403/not_authenticated` by clearing private state and reauthenticating. On `403/csrf_failed` refresh the token and follow the operation-specific replay rules. Handle use or object denials in place per endpoint. Show management navigation only from a server-provided role or capability. The server authorizes each operation.
- Cancel superseded reads (for example with `AbortController`) and gate responses by canonical query, request generation and current session. On revocation, logout or user switch, invalidate protected chart, table, detail and export state, including in-flight responses. Respect private `no-store` responses. Render redacted fields and private-object errors without disclosing identities or counts indirectly.
- Consume authorized server products, projections, time windows, ranking, coverage and quality states. The prototype's client-side fixture arithmetic, mock roles and pagination belong to the demonstration. Reuse the applied parent query and its correct version for research details/exports. Restart changed pages from the first cursor. Re-read versions and original receipts before any permitted retry of a high-impact write. Surface contract gaps against S07 for a separate decision.

## Delivery evidence

- Use `frontend-delivery` for frontend delivery and design discovery. Use `design-taste-frontend` (installed as `taste-skill`) or `ui-ux-pro-max` for applicable design questions, `impeccable` for focused polish, `web-design-guidelines` for applicable interface/accessibility reviews and Playwright (`playwright-cli` or the project's runner) for real browser evidence. Choose the tools needed by the change. Keep shared decisions in the adjacent DESIGN.md when a skill offers to generate its own design files.
- Use the lockfile for reproducible installs. Run the relevant TypeScript checks, Vitest tests and Vite build scripts once they exist in the formal app. For a meaningful visual or interaction change, open the affected route and verify the states in DESIGN.md with representative desktop/narrow viewports, keyboard, and zoom or pointer modes where relevant. Check open overlays, stable map/table/chart selection, rapid queries, return context, material fallbacks, console errors and performance according to risk. Keep comparable screenshots for visual regressions using data permitted for the evidence audience.
- For integration claims use the actual v1 session and authorized server responses in an isolated verification environment. Label F, licensed H, injected failure and authorized real-source evidence separately. Report `PASS`, `FAIL` or `NOT RUN` with the environment and limits. When adding or changing a shared token or component, reconcile the implementation, DESIGN.md and the relevant visual evidence together.
