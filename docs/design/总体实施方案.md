# 基于爬虫与可视化的城市空气质量监测数据分析平台——总体实施方案

**实施路线**　先让一条获准样本经过任务处理、数据库写入和登录查询，再扩展采集、分析和管理业务。后端通过独立验收后启动正式前端。城市在线运行按来源许可和现场验证结果另行判定。

**设计基线**　工作区 V3.0 最终整合版，设计基准日 2026-11-20，SHA-256 `4373fca30fd71061c4e795ebd02b73190e39d451dd7830c0dc5bf01e58379bf6`。已核对两项最终修正。§7.2 与 T06 要求同值可信新版推进来源版本水位，迟到旧版保留为事件。§6.3 与 T08 要求留存期限届满或留存权撤回时实际处置数据及受控副本。依据见[总体设计 V3.0](城市空气质量监测数据分析平台_系统总体设计方案_V3.0.md)。

**当前状态**　总体设计有条件通过，完整城市在线业务为 **NO-GO**。以下九阶段均为后续开发和验收目标。三轮原型证据的适用范围见第 2 章，设计审查结论见[既有终审](../../../design-review/FINAL_REVIEW.md)。

## 1. 实施目标与总体原则

项目服务于城市和监测站点两层业务，部署在可复现的单机环境。普通用户可以从全国概览进入城市和站点，比较同层对象、核对统计明细、收藏或导出获准数据。管理员可以从一个采集窗口查出应到和缺失的观测、处理经过，以及哪些用户查询受到了影响。

| 正式开发中的取舍 | 实施原则 |
|---|---|
| 交付单位 | 每次围绕一项用户或管理员行为，同时交付领域规则、存储、权限、读写入口和失败路径的测试。最终按七个用户模块和三个管理模块验收 |
| 数据依据 | 软件验证使用获准历史或项目自制夹具。城市官值、真实发布、地图点位和长期在线稳定性各需对应的真实证据 |
| 优先级 | P0 覆盖十模块最小闭环。可靠采集、质量治理和多维统计三项重点 P1 随相关业务建设，P2 按第 10 章收口 |
| 工程规模 | 首版面向毕业设计和本地答辩，采用单体和一个主数据库。微服务、Kubernetes、Kafka、Elasticsearch、TimescaleDB、预测、AI 报告及商业网关均在本期范围之外 |

**数据产品简称**取自 V3.0。L 为全国城市同刻 AQI 列表，C 为城市直接实况，S 为按城站点实况，T 为独立的城市近期 AQI 趋势，D 为需另行核实的官方日报。H 为获准历史站点产品。F 为项目自制夹具，使用独立命名空间并标明合成。

## 2. 工程起点与开源复用策略

正式开发获准后，**新建独立 Git 单仓库，以 Django 官方工程为起点**。研究工作区保留设计和验证证据。相比整体 Fork 第三方平台，官方工程能直接采用 V3.0 的观测身份、任务窗口和权限边界，减少改造既有数据模型的工作。原型优先复用字段映射、断言和对账方法。迁入代码前核对来源、许可证与署名义务、依赖兼容性、V3.0 语义和回归测试。代码许可、观测数据许可、地图素材许可分别登记。

## 3. 总体工程组织

采用前后端分离的单仓库和**一个 Django 模块化单体**。Web、Worker、Beat 在各自进程中运行，使用同一套领域服务、配置和数据库迁移。下文以 PG 简称 PostgreSQL。

| 边界 | 负责 | 不负责 |
|---|---|---|
| Web 与业务领域 | DRF 同源 REST/JSON。账户与私有资源、来源与地理目录、城市/站点观测、质量与修订、统一查询、统计、导出、受控管理 | 用户查询不直连 CNEMC。Admin 只维护账号和低风险字典，不能裸改官方观测 |
| 任务进程 | 单一 Beat 排期，Redis 传递消息，Worker 执行 HTTPX 产品适配、受控文件导入、质量处理和获准重算。手动与定时共用业务规则 | 不把 Redis、日志或 Celery 返回状态当作窗口终态、版本水位或授权依据 |
| 数据与分析 | PostgreSQL 保存观测版本、许可、窗口及子项、质量事件、用户和派生依赖。SQL 优先筛选、对齐、计数、聚合，限量子集交 Pandas/NumPy | 不全库拉入内存，不为绘图修改事实。无负载证据不预建汇总层或分区 |
| 前端与交付资源 | 一个 Vue 工程承载用户端和按权限进入的业务管理台。仓内维护契约、测试、合法夹具说明、Compose 本地运行及恢复说明 | 不复制后端的统计或许可判断。数据库和 Redis 不以公网服务交付。不把受限原文、密钥或个人数据纳入仓库或镜像 |

## 4. 总体开发路线

第一条链只选一个获准历史样本或独立合成夹具（F），实际使用 Session、任务进程、领域处理、PostgreSQL 和查询 API。随后先固定“哪种产品、哪个实体、哪个观测、谁可用”的含义，再扩展采集与读端，避免已经积累的数据因主键或口径错误而返工。分析复用经授权的明细，管理服务复用已经存在的任务账和质量事件，不另建平行事实库。

S01、S02 完成后，采集可靠性（S03）和用户查询（S04）可独立推进。单人可按表中顺序实施。真实来源仍待准入时，S03 可用本地合成响应检验任务可靠性，S04 可直接使用合法本地数据。S05 依赖 S02/S04 的产品语义和选数结果。S06 将 S03～S05 的任务、查询和分析接入治理，S07 独立验证后端。S08 开始正式前端，S09 验收集成版本。来源许可与地图材料可从早期核实，城市受限试运行和正式在线验收的条件见第 9 章。

## 5. 实施阶段规划

下表给出单人实施的推荐顺序。各阶段的硬依赖和完成条件列在表后。

| 阶段 | 主要目标 | 交付物或退出标志 |
|---|---|---|
| S01 可运行骨架 | 在没有正式页面和外部源的情况下打通一条观测 | 可复现的登录、任务写入、API 回读和拒绝用例 |
| S02 数据底座与历史导入 | 建立来源权利记录，确定产品、身份、时间、质量与版本的含义 | 可对账的 H/F 导入、当前值与修订证据、受控读取 |
| S03 自主采集与窗口对账 | 将一次网络请求转化为可恢复、可解释的窗口结果 | 分产品适配器、定时/手动任务、部分成功和恢复账本 |
| S04 查询与个人业务 | 让用户从概览查到站点和明细，并安全复访 | 同口径查询、逐指标新鲜度、账户与收藏服务 |
| S05 比较、统计与受控导出 | 在可比样本上形成可复算的结论 | 带分母的分析结果、明细下钻、私有分析条件与限量导出 |
| S06 质量治理与运行管理 | 让管理员从失败记录查到受影响的数据和用户查询 | 争议裁决、失效/重算、留存处置、恢复与健康管理能力 |
| S07 后端独立验收 | 在没有正式前端的条件下证明后端可交接 | 可重建的验收环境、契约基线、性能和故障报告及未放行项 |
| S08 正式前端 | 基于稳定后端完成用户分析和管理员治理界面 | 原创用户界面、管理工作台、浏览器联调与可用性证据 |
| S09 集成与交付 | 分别判定本地系统、地图和真实在线是否达标 | 可复现交付包、逐项验收矩阵、限定范围的放行结论 |

### S01 可运行骨架与第一条纵向链路

- **目标与模块**　先证明基础设施能协作。涉及 M07 身份、M08 任务、M09 基本校验、M06 回读、M10 启动状态。落实 D01、D10、D12 的基础，不建十套空模块。
- **建设**　独立仓库、Python 3.13/uv 锁依赖、Ruff 与自动化测试。Django/DRF 连真实 PG，Redis、独立 Worker 和唯一 Beat 可在本地 Compose 下运行。注册仅为 USER，建立同源 Session、登录及写操作的 CSRF 校验、管理员受控入口。保留最小产品、对象、时间、单位和用途标记。在线计划默认关闭。
- **依赖**　沿用首轮的部署拓扑、会话测试与样本处理经验。仅需本地环境与自制 F，或确有用途依据的 H，不依赖 CNEMC。
- **交付**　可重建的小系统。经授权触发一次样本任务，Worker 处理并持久化，登录用户可按产品和时刻查回该样本。夹具没有进入真实数据空间。
- **验收**　从空的本地测试环境启动并迁移，真实任务进程消费消息。对照输入、PG 记录及带单位和时刻的 API 输出，重启服务后结果仍在。未登录查询、无 CSRF 的状态变更、普通用户触发管理动作均被拒绝，自动化测试可重复。
- **边界**　这里只打通一个最小产品和用例。完整字典与版本裁决归 S02，窗口调度归 S03，个人业务归 S04。

### S02 数据底座、修订规则与受控历史导入

- **目标与模块**　消除“同一城市同一小时就是同一条数据”的错误前提，为 M01～M06、M08、M09 提供共同语义。核心决策 D02～D05、D07。
- **建设**　登记产品、地域、受众、用途、期限和依据，未明确的用途默认拒绝。城市与站点观测分别存放。用来源命名空间与站码识别站点，缺少官方站码的 H 使用数据集内部身份。站址有效期和城市归属各自有据可查。逻辑观测键包含产品来源、实体/站址期、报告类型及窗口、观测时刻或地方报告日、标准系列。建立规范内容、可信源版本标记、修订、批次及质量事件之间的关系。受控文件导入与将来的 HTTPX 适配器走同一规范化入口。
- **依赖**　S01。按 CC BY 4.0 署名并核实适用用途，用 UCI 北京站点 H 做真实历史对账，用独立 F 制造城市、迁址及版本反例。香港验证数据、CNEMC 回执不作种子。无需外部在线请求。
- **交付**　可重复导入且能追溯的数据集、产品/许可目录、当前观测与争议查询。受限批次不会进入默认查询。记录三类时间、来源时区、UTC 时刻/地方报告日、单位与统计窗口，区分缺键、缺测、删失、真零、待核异常和不兼容标准。
- **验收**　同批重导不增观测。UCI 的 CO 换算可与原样本核对，不产生城市 AQI。跨源同名站不合并，迁址前后仍能查到各自站址期。按 §6 的 T06 反例验证“同值推进水位、迟到不回滚”。同版异值或不能排序的异值留下候选与事件，不凭抓取时刻或包哈希决胜。入库前拒绝没有保存依据的输入。展示权撤回后用户查询停止返回该样本，仍获准的内部留存和用途分别处理。
- **边界**　此处确立处置、版本与依赖的规则，已有数据形态就要受控。后续每出现一种新派生物即接入，S06 再全链演练。此时不做运营看板、在线调度或全量预聚合。

### S03 分产品自主采集与可恢复的窗口账本

- **目标与模块**　建成 M08 的任务系统，并为 M09/M10 提供可查的事实。先有 S02 的观测身份和质量定义，才能解释重投究竟新增了什么。落实 D02、D06、D07。
- **建设**　L/C/S/T 按产品独立配置、独立解析与对账。D 仅在核实字段、窗口和用途后接入。HTTPX 适配器按配置发起请求，限制等待时间和响应体积，校验结构后交出候选记录。H 导入走共用入库服务。定时、手动、重试争用同一个业务窗口，区分计划 Job、窗口 WorkWindow、运行 Run、稳定子项尝试 RunItem、获取批次 Batch。PG 事务认领，租约到期可回收，以所有者代次拒绝旧 Worker 回写。观测入库与有效子项回执一致提交，可恢复待投递/过期项。
- **依赖**　S01/S02、第二轮重投与断源场景、第三轮字段契约与解析断言。常规验收使用本地合成响应，由真实 Worker 消费任务并写入 PG。真实请求只有在相应产品、频率与用途另获准后才允许。
- **交付**　交付可暂停和恢复的任务，以及按窗口、产品、对象和指标核算的对账结果。对账区分应到、实到、有效和缺失，并列出新增、重复、修订和隔离记录。缺口分别标记上游未报、本站未取、产品无该指标、字段异常和权限失效，证据不足时记原因待核。运行能区分新发布、请求成功无新发布、部分成功、失败、暂停或未授权。分别记录观测、获取和任务时刻，由观测时刻计算数据年龄。
- **验收**　让定时、手动和重试同时指向一个窗口，注入 Worker 中断、消息重投和失去租约后的迟到回写。同一子项仅认可一次有效提交，窗口只有一个完成事实，部分成功时可查已完成子项及剩余缺口。临时错误按有界指数退避重试，权限拒绝、明确限流/429 或重大结构漂移暂停并记录。HTTP 200 空包/无新发布不更新观测时刻。只有上游已证实可回溯且当前获准的同产品同历史窗才补采。其余缺口可查，历史窗口的覆盖由该窗实到子项单独核算（T05）。
- **边界**　本阶段交付离线可验证的采集软件。实源覆盖、实际成功率及持续试运行由第 9 章的在线验收给出结论。

### S04 统一查询与用户业务闭环

- **目标与模块**　贯通 M01 全国、M02 城市、M03 站点、M06 明细、M07 账户和收藏，为 M04/M05 提供同一选数入口，落实 D02、D05、D09～D11。
- **建设**　全国总览按城市名称和地域筛选同一观测时刻的 L，给出实际覆盖城市数、AQI 排名、等级分布与首要污染物。城市七项取 C，T 单列近 24 小时 AQI，历史查询读取合法积累的 C。站点按 S 或独立 H、站址期和指标取值。区分“最近有效”与“指定时间窗”，支持来源、指标、单位/窗口、标准和质量筛选及稳定分页。完善注册登录/退出、改密、资料、收藏去重与我的关注。停站不换对象，撤权保留意图不显示受限数据。

**产品约束（D02）**随服务端查询交付。L 的六个污染物等级字段用于展示等级。城市七项来自 C 的同一个城市对象，T 只用于独立的近期趋势。站点比较在同类 S 或 H 内进行。官方日报取自核实后的 D。产品、站址或标准不兼容时保留各自序列并加以说明。F 的观测只参与标明用途的合成测试或演示，真实统计与在线验收排除 F。

| 后端关键问题 | 验收观察与判据 |
|---|---|
| **T06　重复读、可信新版和内容订正是否分得开？** | 同一逻辑键依次收到 `v1 = 10`、`v3 = 10`、迟到的 `v2 = 20`。应只有 **1 条有效观测，当前值 10，可信来源版本 v3**。v3 有证据、水位推进但沿用内容修订，v2 有迟到事件，统计和导出不回退。若仅水位变化且含义、用途、统计输入均未变，可沿用统计。有可信异值新版则保留旧修订、晋升新当前值，并按血缘失效/重算。本站映射纠错单列。同版异值或无可信顺序的异值隔离，不能让管理员手改官值“消除冲突”。S02 核对观测身份与计数，S05/S06 核对统计和导出，S07 在同一验收环境重复整条链路。 |
| **T04　怎样核对共同比较时槽？** | E 是按产品节奏和实际应覆盖窗口**应有**的时槽。O 是收到记录的独立时槽（该指标为空也可能实到）。V 是口径兼容且有效的时槽。E共按发布节奏取各对象**共同应有**的时槽，即使某对象在其中漏报，该时槽仍计入分母。P 是 E共内全体共同有效的时槽。单对象报告 O/E、V/E，多对象报告 P/E共。另列请求全窗与按发布安排应覆盖的时窗。E 未知时标明比例不可计算，分母为零不出整期结论。两站各 18/24 有效、共同仅 12/24 时，保留对齐明细和曲线，**不得按全天排名**。V/E ≥ 75% 才支持单序列整期解释，P/E共 ≥ 75% 才支持整期多对象比较。Pearson 还须 P ≥ 30 且两列方差均非零。均为本站探索门槛，非法定标准。 |
| **数值、标准和新鲜度有据可查吗？** | 同时保留原始时间语义、观测/获取/执行时刻和来源时区。没有可信发布时间只报观测年龄。区分 CNEMC CO 的 mg/m³ 与 UCI CO 的 µg/m³、小时 O₃ 与滚动 8 小时/日报。`<3`、缺测和真零不能合并，物理可行的高峰先待核。按 V3.0 §8.2 的版本依据分段。2026-03-01 前后不能只凭采集日期套标准。2012 版一级 0–50，2026 版一级 1–50，后者 AQI 的 0 或 >500 保留原值并待核。未知版本不混排、不擅自着色。季节统计按标准和站址分段，列出各月有效样本和不完整季节。相关性不解释为因果。 |
| **T08　仅失去展示权与失去留存权有什么不同？** | 许可按产品×操作×受众×地域×期限及频率判定。仅展示权失效时，停止相关展示，清除受影响的展示缓存并屏蔽相应派生输出。其余仍有依据的留存和用途继续。留存期限届满或留存权撤回，按适用许可及法律义务**删除、不可逆匿名化或执行其他明确允许的处置**。核对规范化观测、原始响应、修订、派生物、缓存、受控导出副本及备份。保全未受影响且有依据的部分，不承诺召回已脱离平台控制的副本。处置审计只留来源、范围、时间、结果等必要信息，不留无权保留的观测内容。 |
| **T08　恢复旧备份会不会复活受限数据？** | 备份受同一留存约束。不能逐项处置的，仅在有明确继续留存依据时隔离并限制访问/恢复，最迟到适用期限按约处置。没有继续留存依据则立即处置。须整份处置时，在期限内先保全仍获准且未受影响的数据。恢复先隔离，依据**备份之外的现行许可与撤回记录**排除无权数据，不能排除就拒绝恢复。用处置前后库和受控副本核对、备份到期/处置记录、拒绝恢复或干净恢复的抽查证明。仅隐藏 UI、撤下链接都不算完成。 |

| 选择条件 | 对象层级与稳定身份、产品/指标、单位与统计窗口、标准/质量条件、绝对时段或相对时间锚、来源时区与粒度。最近有效、指定历史窗、可比统计为三种明确模式。服务端原样保留用户指定的来源、窗口和范围 |
| 查询结果 | 当前条件、实际覆盖、逐指标观测时刻/获取时刻/年龄、来源、数据版本和质量状态。只对当前受众给出可展示、可统计或可下载的操作提示。分析另给方法/门槛、E/O/V/E共/P、排除和证据不足原因。地图、图表、明细、收藏回访和导出使用同一服务端语义。可批量取摘要，不逐卡访问数据库 |
| 排序、分页和状态 | 明细先按观测时刻排序，同一时刻再按唯一标识排序。返回页/游标及范围限制。在相同授权和数据集下，各页合并后应与完整有序结果一致。区分参数错误、未登录、无对象/用途权限、合法空集、未覆盖、陈旧、源失败或结构异常、系统错误。只披露授权范围的信息，不能用计数、错误详情或缓存旁路泄漏 |
| 身份与敏感操作 | 同源 Cookie（会话 HttpOnly，适当 SameSite，HTTPS 时 Secure）。登录本身和所有改变状态的浏览器请求都校验 CSRF。失效会话引导重登。角色、对象所有权、来源用途始终由后端判断，按钮状态只作提示。访问私有方案或领取文件时重新检查当前条件 |

**前端启动条件**　S07 提供可复现环境，以及正常、空窗、旧值、部分成功、拒绝、修订/撤权等合法样例。使用对应角色的账户，可以走通三条业务链的后端部分。此后产品身份、时槽分母、版本含义、分页及主要错误语义不作随意破坏性调整。必要修正同步更新契约、测试和调用方，以新旧同条件的结果核对修正效果。S08 才编制专门设计规范，以同一套环境科技视觉语言组织用户地图和统计下钻。管理员优先高效检索和处置，不照套用户端卡片。响应式、键盘操作、文字图例、断档、低动效体验及无外部 CDN 的可读性都在真实浏览器验收。

## 8. 跨阶段工程质量保障

| 何时建立证据 | 检查及不通过时的处理 |
|---|---|
| S01 起，每次扩大业务时 | 依赖锁定、Ruff、关键边界类型检查、pytest/pytest-django。纯规则用小样，事务、约束、跨进程行为用真实 PG/Redis/Worker，HTTP 用真实会话。区分 H、F、获准实源、真实故障与注入故障。不以 Mock 的成功抵销集成失败 |
| S02～S06，写入或用途变化时 | 每次交付同时验证正常路径和反例，覆盖错误单位/时间、重放、冲突、修订、角色越权及跨用户读写等情况。同一产品“可展示不可下载”“可留存不可展示”“不可再留存”分别核对。计划/投递、实际请求、写入、读取、统计、生成/下载及备份恢复都复核许可。撤回即停止相应用途及其重试。导入和网络响应限制来源、格式、大小、行数。登录/敏感操作限速。日志不含凭据、会话或可还原且无保存权的原文 |
| S03～S07，负载与故障出现时 | 先做批量写、投影、稳定分页、对象/产品/时间与当前版本等实际查询所需的复合索引。保存脱敏关联号、数据库执行计划、重投后计数与窗口差额。优化前后用相同负载复测。只有确有瓶颈才考虑可失效、可重算的汇总或分区 |
| S07 测后端，S08/S09 单独测量浏览器绘图耗时 | **V3.0 §10.2 的验收预算**适用于本地 Compose、百万合成小时行和 5 名并发已登录用户。通过预热的同源 HTTP 测量，单对象 24 小时查询或 100 行一页明细 P95 ≤ 1 秒。最多 5 对象×30 天单指标小时序列或单对象一年按月浓度汇总，P95 ≤ 2 秒。冷态、预热分别测，记录机器/内存、行数、并发、缓存、SQL 计划、HTTP P95 与错误率。浏览器渲染另计。绘图默认 ≤1,000 点，超出用保留极值与断档的桶，不改计算分母或 CSV。规定负载超预算时，按执行计划优化并以相同负载复验。对于超过支持范围的请求，提示用户缩小范围 |
| S07～S09，交接和交付时 | 从干净环境重建，验证服务重启、持久卷、隔离恢复和无外网冷启。离线资源预备与合法署名可随交付说明核查。S08 加入 TypeScript 检查、Vitest 和 Playwright 用户/管理员流程。S09 在同一交付版本核对 T01～T12。记录环境、基线、输入类别、预期、实得及证据位置。PASS、FAIL、NOT RUN 和被外部条件阻塞分开标明 |

## 9. 数据来源准入与风险管理

V3.0 §12.4 分别规定基础软件开发、受限试运行和正式在线运行的条件。下表列出六项会影响这些阶段的风险。

1. **基础软件线。** 获准开展开发后，以有相应用途依据并署名的 H（如 UCI 北京历史站点）和隔离 F 验证 S01～S08 的软件能力及 S09 的本地部分。真实历史分析须用 H，真实地图另需合规素材和点位。UCI 无官方城市 AQI、正式站码和坐标，不得冒充内地城市历史。默认不开外采。无原文保存权不落原包、可还原日志或截图，摘要与哈希也先查用途。
2. **进入受限试运行前。** 先为拟用产品、地域、请求频率/配额、必要持久化、目标受众展示等实际用途取得可核依据。统计、截图、明细/汇总导出、备份等按各自用途另判。在允许范围内现场核查京沪穗或证据充分的等价三地区，**每地区至少两个不同的真实发布周期**，核对官方城市七项、单位/窗口、观测时刻、发布/获取时延可测边界及修订/缺项。已有浏览器三城两期、独立 HTTPX 京沪两期，**广州独立 HTTPX 仅一期**。重复读取同一时刻不算跨期。另将获准城市样本真正走通 Celery→PostgreSQL→查询、同样本重放和断源冷启动展示。站点样本不代替。证据齐备后，冻结产品/地域、周期、成功率、新鲜度及允许缺口阈值，**另行批准受限试运行**。许可核实可早做，实际前置验证只在有权且相应链路就绪时做。
3. **城市在线正式验收（T11）。** 仅从获准试运行起算，**自然经过 168 小时**。用窗口账本按事先冻结的判据核新观测、覆盖缺口、观测年龄、失败/重试及修订。没有真实订正就如实记录，不能用注入制造“发生过”。达标且经正式复审，才可在批准范围内记 GO。计时、历史回放、合成用例和 HTTP 响应可作辅助记录，T11 只认可受限试运行期间的真实发布及其窗口对账。导出权未获准则关闭该用途，不必否决已经单独获准且验收合格的展示/分析。

| V3.0 风险 | 影响哪一步 | 应对措施与解除条件 |
|---|---|---|
| R1 来源用途与受众 | S02 起全链、S09 在线 | 按用途默认拒绝，继续 H/F。以适用条款或授权证据及生效/失效范围放行相应动作，不从公开访问或开源代码许可证推断 |
| R2 真实发布与更新 | S03、S09/T11 | 离线验证解析与异常，保留真实跨期/时延/自然 168 小时缺口。只有实源回执、获准城市链与冻结判据下的试运行报告可解除 |
| R3 站址、坐标和底图 | S02、S04、S08/S09 | 无可信关联保留独立身份，无合规地理材料保留列表。核对站址有效期、真实点位、坐标系与几何素材使用条件才可验地图 |

### 10.2 三种完成状态不能混称

| 可作的判断 | 必须具备的证据 | 不得推定 |
|---|---|---|
| **后端稳定，可启动前端** | S07 通过后，十模块所需服务、权限和异常处理在合法测试范围内独立可用。接口契约示例与真实行为相符。事务、版本、用途、冷热负载与本地恢复可复现 | 不代表浏览器体验、正式地图或在线业务已通过 |
| **本地集成版本可交付** | 可用 Compose 重建，登录后走通用户、管理员、研究三条链。没有城市场景实源许可时，用明确标识的 F 验证城市软件链路，用获准 H 验证真实站点分析。离线冷启及持久化实测，样本、软件与素材归属清楚，性能/可用性有记录。尚缺的城市、地图或在线证据逐项列明 | 列表不能代替地图、H 不能代替城市，不能写“所有 P0 已通过” |
| **V3.0 完整系统在声明范围内完成** | 对每个 M 的 P0 核对行为、输入类别、适用许可、交付版本和可复核证据，T01～T12 均在各自规定的场景有通过证据。三项重点 P1 另按下述条件报告实际深度。地图及真实城市离线分别实测，T11 经受限试运行达标及正式复审获准。只在批准受众、地域、产品和用途中给出结论 | 不扩大为全国永久覆盖、公开再分发或无限制历史补采，不把仍阻塞的必需项记为 PASS |

**重点 P1 的交付条件**

1. S03/S06 能区分可补与不可补的历史缺口，仅对允许的缺口恢复执行，已认可的子项提交保持唯一。
2. S02/S06 能追溯争议与影响窗口，给出质量覆盖及必要重算结果。
3. S05 能以同质时槽产出带样本条件的多维统计，并在条件不足时拒绝结论。

其余 P1 随归属模块分别记录交付状态，如站点覆盖日历、两期同城变化、获准汇总导出或运行趋势。持久化聚合须有必要性证据。版本不回滚、失效传播、部分成功与用途拒绝是正确性底线，不得以“P1 未做”豁免。**P2** 的历史地图回放、更复杂个性化及少量辅助气象变量可不交付，不影响已满足条件的核心系统验收。

## 11. 实施范围与总体结论

正式工程从“一个合法样本可写、可读、可追溯”开始。当多个产品、多个对象和多次投递仍能保持正确时，再开放统计、隐私资源和管理操作。后端交接依据 S07 的业务、性能和恢复证据。S08/S09 通过浏览器和本地部署检验用户能否走通三条主流程。真实城市在线运行依 T11 的试运行记录和正式复审结论放行。

本轮交付范围为总体实施方案。各阶段的详细实施计划留待相应阶段正式启动时制定。当前进度止于规划，正式开发从后续另行启动的 S01 开始。
