# v1 接口候选与调用样例

OpenAPI 3.1 JSON 列出全部显式 v1 操作、请求参数、成功状态、错误和响应类型。[openapi.v1.json](openapi.v1.json)

S07 交接保留候选状态，验收和封版取决于独立阶段审查。[S07 Implementation Plan](../plans/S07_IMPLEMENTATION_PLAN.md#6-风险封版与独立交接)

## 同源会话

1. 在每位用户独立的 Cookie jar 中执行 `GET /api/v1/auth/csrf/`。保留 `csrftoken` Cookie，并读取 JSON 的 `csrf_token`。
2. 发送 `POST /api/v1/auth/login/`，请求体为 `{"username":"…","password":"…"}`，使用 `Content-Type: application/json` 和本次 `X-CSRFToken`。注册先走同一 CSRF 引导，再向 `POST /api/v1/auth/register/` 提交用户名和密码。注册创建普通用户，登录另行发起。
3. 登录后再次执行 `GET /api/v1/auth/csrf/`，使用新 token 发送写请求。`sessionid` 为 HttpOnly、SameSite=Lax，有效期 8 小时。`COOKIE_SECURE=1` 时 `sessionid` 和 `csrftoken` 均要求 HTTPS。JSON 请求体上限为 16 KiB。
4. 改密码、退出和停用均有 Session 失效场景。客户端收到 `403/not_authenticated` 后重新登录。`403/csrf_failed` 时重新获取 token，并按操作的重放规则判断能否重试。

## 普通用户的 F 请求

1. 调用 `GET /api/v1/me/` 和 `GET /api/v1/catalog/objects/?scope=synthetic`。跟随获权产品的 `link` 进入全国 L、城市 C、趋势 T 或站点 S。城市七指标来自 C。T 为独立 AQI 序列，站点数据关联具体站址期。目录提供 `history_link` 时，用它进入获权历史窗。坐标和 CRS 缺少依据时可能为空。
2. 在 F 环境请求显式窗口。以下路径中的 `<C>` 和 `<city>` 取自上一跳。空窗可返回 `200`、`state=no_data` 和空数组。

   ```http
   GET /api/v1/observations/query/?scope=synthetic&product=<C>&cities=<city>&mode=window&indicators=CO&report_kind=hourly&window_definition=hourly_label_unspecified&start=2024-02-01T00:00:00Z&end=2024-02-02T00:00:00Z
   ```

3. 向 `POST /api/v1/analysis/statistics/` 提交以下模板。将 `<C>` 和 `<city>` 换成目录卡片中的产品和城市正整数 ID。`<source>` 使用同一卡片 `source` 字段的命名空间字符串。向 `POST /api/v1/analysis/details/` 提交同一父查询并附上统计响应顶层 `input_version`。翻页时保持父查询、`support` 和 `page_size`，使用响应的 `page.next_cursor`。

   ```text
   {
     "selection": {
       "product": <C>, "source": "<source>", "scope": "synthetic",
       "cities": [<city>], "indicators": ["CO"],
       "start": "2024-02-01T00:00:00Z", "end": "2024-02-02T00:00:00Z"
     },
     "method": "statistics", "method_version": "s05.v1", "grain": "day"
   }
   ```

4. 保存查询使用同一父查询并增加 `title`，提交到 `POST /api/v1/me/saved-queries/`。复访调用 `POST /api/v1/me/saved-queries/{id}/run/?scope=synthetic`，系统按当时许可和数据重跑。`PATCH` 需要当前 `intent_revision`。
5. 准备明细 CSV 使用 `POST /api/v1/me/exports/`。请求包含 `kind=detail`、`fields=[]`，以及 `groups` 数组。数组中的每个对象为上述父查询及其研究 `input_version`。用返回的票据 ID 调用 `GET /api/v1/me/exports/{id}/download/?scope=synthetic`。成功返回附件和 `text/csv; charset=utf-8`。版本已变化时按 `409/input_changed` 重新查询、申请新票。另一个用户读取同一票据时按私有对象返回 `404/not_found`。到期返回 `410/expired`。拒绝响应为 JSON，且无下载附件头。
6. `POST /api/v1/auth/logout/` 成功返回 204。再次访问 `GET /api/v1/me/` 可核对原会话已失效。

GET 明细将同类对象和指标编码为逗号分隔值，正式域省略 `scope`。研究 POST 使用数组及可选的 `units`、`standard_series` 映射，`scope` 可取 `formal` 或 `synthetic`。显式 `[start,end)` 和 `latest_valid/as_of` 分别选择固定窗口或截止时刻最近有效值。日期时间带 ISO 8601 偏移，地方日报和地方日统计以源时区划界。观测十进制值使用 JSON 字符串，允许 `null`，统计量和计数使用 JSON 数字。各路径的默认排序及限制见 OpenAPI operation 描述。

分页游标绑定用户、路由、筛选、页大小和相关输入。S04 签发的游标有效期为 3,600 秒。页输入变化可能返回 `409/page_changed` 或 `409/input_changed`，此时从该查询第一页重取。

## 管理员的 F 请求

1. 使用具名权限账号独立登录。从 `GET /api/v1/admin/collection-jobs/?scope=synthetic` 选择获权 Job，跟随 `links.detail` 核查控制版本和目标范围。
2. 调用 `POST /api/v1/admin/collection-runs/` 提交自有 F Job、目标小时、理由和规范 UUID。投递成功返回 202。投递未确认可能返回含 `run_id` 的 503，可用原 ID 查账并按恢复契约重投。跟随 Run 和 Window 详情以及质量入口查看业务窗、批次和覆盖，使用 `GET /api/v1/admin/operations/health/?window=<window>` 查看获权运行状态。显式源地方日期区间的趋势由 `GET /api/v1/admin/operations/trends/` 提供。
3. 使用 `GET /api/v1/admin/accounts/{pk}/actions/` 核对账户控制版本，再由具名权限账号提交 `{"action":"disable","request_id":"<本次规范 UUID>","reason_code":"account_review","expected_version":<当前版本>}`。检查 `action_id`、`active` 和 `version`。同一意图的合法重放沿用原 UUID。过期版本返回 409，账号越界和缺 CSRF 按实际端点返回 404 或 403。
4. 历史导入的暂存 ID 由受控主机流程注册。操作者或获准审阅者查询其状态。备份签认、清理和恢复使用现有受控主机命令，JSON 接口处理获权状态、动作或意图。[受控备份和隔离恢复](../operations/S07_handoff.md#受控备份和隔离恢复)

真实 F/I 客户端与隔离运行器会创建本轮数据，使用独立 Session 和临时凭据。直接执行以下命令复跑样例，随后按 V01 与操作收据核对状态。

```bash
.venv/bin/python -B scripts/verify_s07_host.py r pytest tests/test_s07_contract.py tests/test_s07_contract_user_http.py tests/test_s07_exact.py
.venv/bin/python -B scripts/verify_s07_host.py contract
.venv/bin/python -B scripts/s07_contract_upgrade.py
```

## 框架边界

| 入口 | 行为 |
| --- | --- |
| `/api/v1/` 显式方法 | JSON 内容及端点列出的 CSV 下载。私有响应带 `Cache-Control: no-store`。框架提前拒绝按规格中各状态的头字段约束处理。 |
| `HEAD`、`OPTIONS` 或其它不支持的方法 | 按实际 DRF 和原生 Django 装饰器处理，也可能返回 405。框架断言覆盖 `me/` 的 OPTIONS/HEAD 和 `auth/csrf/` 的 OPTIONS。 |
| `/admin/` | Django 原生 HTML 管理站。角色和现权限决定可访问对象。 |
| `/health/ready/` | Web 与 PostgreSQL 就绪检查，成功为 200，数据库不可用时为 503。 |
| 未匹配路径及原生 500 | Django HTML 边界。可预期的业务拒绝和已处理数据库异常遵循各 v1 operation 的 JSON 契约。 |

## 精确读迁移与 S05 兼容

`GET /api/v1/observations/current/` 的 `results[].input_version` 原位换为 64 位小写十六进制字符串。将其作为该会话和同一精确选择条件下的等值标记。保留获权的 `revision_id` 和 `rights_attributions`。无需迁移数据库中的业务主键。

| 旧读法或调用者 | 替代读法与核验 |
| --- | --- |
| `input_version.key` / `.revision`，`scripts/s04_checks.py:detail_http` 及复用它的 S05 运行器 | 用结果行的 `revision_id` 和产品、实体、时标、指标对账。通用明细有自己的 `key` / `revision`，独立 PG 键可用于验收。 |
| `input_version.qualification` | 公开读取依据为该行的资格状态和不透明标记。涉及内部资格版本的运维核验由受控领域审核完成。 |
| `input_version.rights`，`tests/test_observation_access.py` | 在真实 PG 核查撤权事件，HTTP 对照 display 拒绝和独立 analyze 权下的原修订及标记。 |
| `input_version.grants`，`tests/test_s04_selection.py` | 在受控 PG 核剩余依据，对外核 `rights_attributions` 和仅有该依据时的等值标记。 |
| `scripts/s02_disposition_checks.py`、`scripts/{s04_checks,s05_runtime_checks}.py`、`tests/{test_history_policy,test_s04_favorites}.py` 的整枚或整包比较 | 同格式继续比较，跨版先对账身份、修订、时标、值、署名和原 Session，再核新标记。 |
| `scripts/s02_history_checks.py`、S03/CNEMC 查询及验证入口、`tests/collection/`、观察与研究回归 | 支持原精确路由、选择、`count/results/reason`、获权的 `revision_id` 与署名。D 继续按源地方报告日精确读取。 |

`rights_version`、`rights` 和 `grants` 的公开别名也被精确读 schema 拒绝。C02 回归验证权外变化稳定、权内变化可察、撤权拒绝及可信修订换标记。同值可信水位推进时，S05 研究输入可能换版，精确读在内容及资格未变时保持标记。

S05 研究响应顶层 `input_version`、`method_version=s05.v1`、`s05.csv.v1` 票据及 CSV 协议独立。研究游标、保存查询和升级前有效票据依原密钥与现权复核。研究请求使用精确读标记时返回 `409/input_changed`。真正变化的研究输入会使旧下钻和受影响票据返回 409。跨版本脚本用升级前实际签发的 Session、游标、保存查询和两张票据检查这些行为，并核对有效票据字节摘要。[票据申请与下载示例](#普通用户的-f-请求)
