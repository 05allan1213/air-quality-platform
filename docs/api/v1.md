## 同源会话

1. 在每位用户独立的 Cookie jar 中执行 `GET /api/v1/auth/csrf/`。保留 `csrftoken` Cookie，并读取 JSON 的 `csrf_token`。
2. 发送 `POST /api/v1/auth/login/`，请求体为 `{"username":"…","password":"…"}`，使用 `Content-Type: application/json` 和本次 `X-CSRFToken`。注册先走同一 CSRF 引导，再向 `POST /api/v1/auth/register/` 提交用户名和密码。注册创建普通用户，登录另行发起。
3. 登录后再次执行 `GET /api/v1/auth/csrf/`，使用新 token 发送写请求。`sessionid` 为 HttpOnly、SameSite=Lax，有效期 8 小时。`COOKIE_SECURE=1` 时 `sessionid` 和 `csrftoken` 均要求 HTTPS。JSON 请求体上限为 16 KiB。
4. 改密码、退出和停用均有 Session 失效场景。客户端收到 `403/not_authenticated` 后重新登录。`403/csrf_failed` 时重新获取 token，并按操作的重放规则判断能否重试。

登录后用 `GET /api/v1/me/capabilities/` 读取当前会话可进入的 `workspaces` 和具名 `actions`。该投影不授予权限；进入具体管理流程后，服务端仍按对象、用途、版本和来源权利逐次核验。响应为私有 `no-store`，不接受查询参数。登出、停用、改密或撤权后应丢弃前端私有状态并重新读取。

```json
{
  "workspaces": ["user", "manage"],
  "actions": ["review_observation", "adjudicate_quality"]
}
```

### S08 工作区能力与研究系列发现

`GET /api/v1/me/capabilities/` 使用当前有效 Session 返回工作区和具名动作。该导航投影不授予对象权限；读/写动作仍在目标端点按当前 Session、对象、用途和数据权重新核验。响应为 `no-store`，不接受查询参数。

`GET /api/v1/catalog/series/` 为研究工作台发现可选数据系列，不读取或暴露原始观测。请求限定 `purpose=analysis`、`method=statistics|compare|pearson` 和带时区的半开 `[start,end)` 窗口（最多 30 天）。可选指定单一 `product`、`city` 或 `site_epoch`、`indicator`；正式域为默认，F 需显式传 `scope=synthetic`。每行给数据产品、实体、指标、单位、报告/窗口定义、标准系列、来源时区和当期获准分析的时间片段。城市和站址期不会混成同一对象。每次最多 50 项，按获权稳定键使用签名游标分页。

目录项只表示该产品/实体/指标/窗口在相应时间片段可用于该分析方法，不代表每个时槽有观测、覆盖完整，也不允许原始曲线或导出。获准发现且没有兼容候选时返回 `200` 和空 `results`。分析提交时，原分析接口会按产品、对象、窗口和标准重新校验组合、权利及数据版本，并可对不兼容组合返回 `422/incompatible_series`。权限或有效期变化后的读取会被拒绝或要求从首页重查。其他域、用途、未知/重复参数、双对象类型、非法时间和越界页大小按业务错误返回。

```text
GET /api/v1/catalog/series/?purpose=analysis&method=statistics&scope=synthetic&product=<C>&city=<city>&indicator=CO&start=2024-02-01T00:00:00Z&end=2024-02-02T00:00:00Z
```

成功示例（ID 保持整数；单位和时间片段由服务端返回）：

```json
{
  "results": [
    {
      "source": "example-source",
      "product": 12,
      "shape": "C",
      "city": 31,
      "indicator": "CO",
      "unit": "mg/m³",
      "report_kind": "hourly",
      "window_definition": "hourly_label_unspecified",
      "standard_series": "not_applicable",
      "source_timezone": "UTC",
      "permitted_from": "2024-02-01T00:00:00+00:00",
      "permitted_until": "2024-02-02T00:00:00+00:00"
    }
  ],
  "page": { "page_size": 25, "next_cursor": null }
}
```

值为字段形状示例；完整访问依据仍取实际响应，不把示例来源/标识当作可用数据。

### 全国 L 总览与首页投影

`GET /api/v1/overview/national/` 继续支持既有列表响应，并提供可选的首页投影。正式域省略 `product` 使用登记的 `cnemc/city-list-hour`；F 必须提供 L 产品并显式传 `scope=synthetic`。`window_definition` 仅接受 `hourly_label_unspecified`、`hourly_left_label`、`hourly_right_label`。`at` 与 `as_of` 互斥，`at` 按来源时区必须为整点；默认按城市 ID 升序，页长默认 50、最大 100。

`order=aqi_desc|aqi_asc` 只改变表格顺序，AQI 相同时以城市 ID 稳定消歧；显式 AQI 顺序及 `grade=1..6` 筛选都需要显式已知 `standard_series` 和汇总权限，等级筛选在分页前生效。缺汇总权限的列表可在 `summary.state=unavailable` 下返回；但明确请求 AQI 顺序或等级筛选会拒绝。普通列表的 `selection` 不含 `home`、`ranking`、`focused` 或 `map`。

附加 `home=1` 后响应仍沿用 `selection/synthetic/snapshot_at/evaluated_at/state/summary/results/page`，并始终增加 `ranking` 和 `focused`。可选 `rank_preview=aqi_desc|aqi_asc` 要求显式已知标准，按同一快照产生最多五行预览；低值方向保留真零，使用 dense rank，并列按城市 ID 展示。`focus_city` 可指向当前筛选/排序结果内、但不在当前页的城市；不可见目标返回 `null`。首页 `page.next_cursor` 绑定独立首页路由、筛选条件、Session 和结果版本，继续请求时必须保留查询条件及页长；榜单方向、聚焦城市和地图限制不改变表格游标条件。

`map_limit=1..400` 只在 `home=1` 时接受。当前仓库没有获准发布的全国地理映射，因此地图固定为 `{ "state": "unavailable", "items": [], "has_more": false }`，不返回点位、经纬度或 CRS。首页响应行严格投影获权的 `series`、`levels` 与 `links`；未获权的名称、地域或导航不由其他字段推断。`ranking` 或 `summary` 可为 unavailable；这些可选区不可用不改变列表的权限和数据语义。未授权、无效参数及游标失效仍分别使用既有拒绝 DTO。

`GET /api/v1/catalog/objects/` 的 L 行先按观测时间选获权记录，同刻优先选获准 AQI。AQI 的 `link` 保留 `at` 和 `window_definition`，已核 AQI 系列附 `standard_series`，未知系列省略该筛选。若选中污染物等级，`link` 等于 `history_link`，按该等级指标的原系列与实际小时窗读取明细。S07 目录游标若以 L 行作为页尾，升级后该行投影变化可触发 `409/page_changed`。保留原条件并移除 `cursor`，从第一页重读。[目录合同与见证](../verification/S08_CONTRACT_DELTA.md#nat-01--nat-02--l-目录与全国快照)

## 普通用户的 F 请求

1. 调用 `GET /api/v1/me/` 和 `GET /api/v1/catalog/objects/?scope=synthetic`。跟随获权产品的 `link` 进入全国 L、城市 C、趋势 T 或站点 S。城市七指标来自 C。T 为独立 AQI 序列，站点数据关联具体站址期。目录提供 `history_link` 时，用它进入获权历史窗。坐标和 CRS 缺少依据时可能为空。
2. 在 F 环境请求显式窗口。以下路径中的 `<C>` 和 `<city>` 取自上一跳。空窗可返回 `200`、`state=no_data` 和空数组。

   ```http
   GET /api/v1/observations/query/?scope=synthetic&product=<C>&cities=<city>&mode=window&indicators=CO&report_kind=hourly&window_definition=hourly_label_unspecified&start=2024-02-01T00:00:00Z&end=2024-02-02T00:00:00Z
   ```

3. 向 `POST /api/v1/analysis/statistics/` 提交以下模板。将 `<C>` 和 `<city>` 换成目录卡片中的产品和城市正整数 ID。`<source>` 使用同一卡片 `source` 字段的命名空间字符串。向 `POST /api/v1/analysis/details/` 提交同一父查询并附上统计响应顶层 `input_version`。翻页时保持父查询、`support` 和 `page_size`，使用响应的 `page.next_cursor`。

   ```text
   {
     "selection": {
       "product": <C>, "source": "<source>", "scope": "synthetic",
       "cities": [<city>], "indicators": ["CO"],
       "start": "2024-02-01T00:00:00Z", "end": "2024-02-02T00:00:00Z"
     },
     "method": "statistics", "method_version": "s05.v1", "grain": "day"
   }
   ```

4. 保存查询使用同一父查询并增加 `title`，提交到 `POST /api/v1/me/saved-queries/`。复访调用 `POST /api/v1/me/saved-queries/{id}/run/?scope=synthetic`，系统按当时许可和数据重跑。`PATCH` 需要当前 `intent_revision`。
5. 准备明细 CSV 使用 `POST /api/v1/me/exports/`。请求包含 `kind=detail`、`fields=[]`，以及 `groups` 数组。数组中的每个对象为上述父查询及其研究 `input_version`。用返回的票据 ID 调用 `GET /api/v1/me/exports/{id}/download/?scope=synthetic`。成功返回附件和 `text/csv; charset=utf-8`。版本已变化时按 `409/input_changed` 重新查询、申请新票。另一个用户读取同一票据时按私有对象返回 `404/not_found`。到期返回 `410/expired`。拒绝响应为 JSON，且无下载附件头。
6. `POST /api/v1/auth/logout/` 成功返回 204。再次访问 `GET /api/v1/me/` 可核对原会话已失效。

GET 明细将同类对象和指标编码为逗号分隔值，正式域省略 `scope`。研究 POST 使用数组及可选的 `units`、`standard_series` 映射，`scope` 可取 `formal` 或 `synthetic`。显式 `[start,end)` 和 `latest_valid/as_of` 分别选择固定窗口或截止时刻最近有效值。日期时间带 ISO 8601 偏移，地方日报和地方日统计以源时区划界。观测十进制值使用 JSON 字符串，允许 `null`，统计量和计数使用 JSON 数字。各路径的默认排序及限制见 OpenAPI operation 描述。

分页游标绑定用户、路由、筛选、页大小和相关输入。S04 签发的游标有效期为 3,600 秒。页输入变化可能返回 `409/page_changed` 或 `409/input_changed`，此时从该查询第一页重取。

## 管理员的 F 请求

1. 使用具名权限账号独立登录。从 `GET /api/v1/admin/collection-jobs/?scope=synthetic` 选择获权 Job，跟随 `links.detail` 核查控制版本和目标范围。
2. 调用 `POST /api/v1/admin/collection-runs/` 提交自有 F Job、目标小时、理由和规范 UUID。投递成功返回 202。投递未确认可能返回含 `run_id` 的 503，可用原 ID 查账并按恢复契约重投。跟随 Run 和 Window 详情以及质量入口查看业务窗、批次和覆盖，使用 `GET /api/v1/admin/operations/health/?window=<window>` 查看获权运行状态。显式源地方日期区间的趋势由 `GET /api/v1/admin/operations/trends/` 提供。
3. 使用 `GET /api/v1/admin/accounts/{pk}/actions/` 核对账户控制版本，再由具名权限账号提交 `{"action":"disable","request_id":"<本次规范 UUID>","reason_code":"account_review","expected_version":<当前版本>}`。检查 `action_id`、`active` 和 `version`。同一意图的合法重放沿用原 UUID。过期版本返回 409，账号越界和缺 CSRF 按实际端点返回 404 或 403。
4. 历史导入的暂存 ID 由受控主机流程注册。操作者或获准审阅者查询其状态。备份签认、清理和恢复使用现有受控主机命令，JSON 接口处理获权状态、动作或意图。[受控备份和隔离恢复](../operations/S07_handoff.md#受控备份和隔离恢复)

## 周期采集配置

调度模板由受控主机操作预先登记；页面仅能看到当前 `observations.configure_collection_schedule` 与来源用途均允许的模板。用 `GET /api/v1/admin/catalog/products/?purpose=configure&scope=synthetic` 分页发现模板及其当前计划。模板中的 `source` 是稳定的来源命名空间字符串，不是数据库 ID。正式域省略 `scope`。游标绑定会话用户、数据域、产品筛选和页大小。

同一路径亦支持获准的执行、账本、质量和运维发现。共有参数为 `purpose,scope,product,page_size,cursor`；`execute` 另需带时区的 UTC 整点 `target` 与 `reason=manual/review/backfill`，`configure` 不带日期。仅 `ledger`、`quality` 和 `operations` 需源地方日期半开范围 `start,end`（最多 30 天）。`execute` 使用 `observations.run_collection`（`review` 原因另需 `observations.review_observation`）；`ledger` 和 `quality` 使用 `observations.review_observation`；`operations` 还需 `accounts.diagnose_operations`。响应顶层统一为 `{results,next_cursor}`；执行行是 `{product,job,reason,target}`，账本/质量/运维行是 `{product,source,shape,links}`。configure 行保持原模板 DTO。

`GET /api/v1/admin/object-audit/` 只接受一个 `kind,id` 及带时区半开 `start,end`（最多 30 天），可带 `page_size`（默认 25、最多 50）和绑定对象/范围的 `cursor`。Run 使用 UUID，其他目标使用正 int64。仅返回当前可披露的 `at,action,outcome,actor_relation,before_version,after_version`，不返回操作者引用或影响链接；无合法可见记录不计入结果与页尾。启用计划记录还需覆盖从原分界起的完整接管范围。该范围部分撤权后，记录及页尾候选都须重新计算。接口与管理产品目录共用逐用户限流，超额返回 `429/rate_limited`。

对未配置模板，用 `POST /api/v1/admin/collection-jobs/` 创建未来的停用草稿；对现有计划，使用 `GET /api/v1/admin/collection-jobs/{pk}/schedule/` 读取控制版本、模板版本、前任版本及预览，再向同一路径 `POST` 提议后继、激活或丢弃。调度 GET 不接收查询参数。每个写入都需新 UUID、对应 `reason_code` 和当前版本。草稿不会投递采集；激活只授权未来计划生效，实际 Run 仍受当前来源、窗口、配额、暂停状态与 Worker 投递规则控制。发生 409 后先重新读取计划，不自动重放。活动计划调整先提议后继草稿，在生效分界交接。启用需完整开放接管段 `[B,+∞)` 的审阅与留存授权。GET 和被拒写入均不会结算交接。

### 本地城市检索别名

具有 `accounts.maintain_city_search_alias` 的活跃 staff 可在 `/admin/observations/city-search-alias/` 读取获权目录。单对象入口为 `/admin/observations/city-search-alias/{product}/{city}/`，需该 L 产品和城市的目录审阅与留存授权。设置或清除须带 CSRF、规范 `request_id`、`expected_version` 和 `reason_code=search_correction`。只在获权 `home=1&q=…` 检索中匹配别名，响应仍显示正式名称。`POST /api/v1/admin/accounts/{pk}/actions/` 的直接授权枚举另支持 `accounts.maintain_city_search_alias` 和 `observations.configure_collection_schedule`。字典单权、可见目录、CSRF、版本冲突和处置见 `s06-ea602791108c`。[字典与账号契约](../verification/S08_CONTRACT_DELTA.md#62--字典本人回执对象审计)

### 本人命令回执和窗口诊断

在写请求响应丢失或投递待核时，向 `POST /api/v1/admin/command-receipts/lookup/` 提交 `{family,target,command}`。`command` 保留原操作完整信封，包括原 UUID、版本、理由及适用的证据引用。目标遵循原写入入口。

| family | target |
|---|---|
| `manual_run`、`job_control` | 原 Job ID |
| `redeliver` | 原 Run UUID |
| `schedule` | 建草稿用模板 ID，提议后继用前驱 Job ID，激活或丢弃用草稿 Job ID |
| `quality`、`station_change`、`grant_withdraw` | 原事件、站点、许可 ID |

查账需要当前 Session 和 CSRF。`200` 返回原提交的动作、记录时刻和状态。治理动作带 `action_id,version`，计划动作还带结果 Job ID。运行类回执给 `run_id,window_id,dispatch,status`。`404/not_found` 表示当前无法核实本人原命令，无从区分未提交、他人命令、信封不符或授权变化。界面保留待核状态，整本 Run 和窗口详情仍按审阅权限读取。调度查账使用原入口、版本和命令。许可变化后按对应原写动作重新核权。真实 Session 的本人回执、调度读取参数拒绝和接管范围部分撤权见 `s06-b7a2ca3f7b1c` 及 `s06-e2acd338648a`。[增量 V12](../verification/S08_V12.json)

`GET /api/v1/admin/operations/health/?window=<id>&include=first_valid_write` 对当前获权窗口增加 `latest_first_valid_write_at`、证据状态、截断标记、可见等待起点、最近抓取时刻与当前 Run 页的错误摘要。首次有效时间取各可见逻辑键首次获得有效当前值的服务端时刻，再取其中最新值。`known` 表示有可证时间，`none` 表示可证没有符合条件的首次写入，`unavailable` 表示无法完整核验。省略 `include` 返回旧投影。

真实 F/I 客户端与隔离运行器会创建本轮数据，使用独立 Session 和临时凭据。直接执行以下命令复跑样例，随后按 V01 与操作收据核对状态。

```bash
.venv/bin/python -B scripts/verify_s07_host.py r pytest tests/test_s07_contract.py tests/test_s07_contract_user_http.py tests/test_s07_exact.py
.venv/bin/python -B scripts/verify_s07_host.py contract
.venv/bin/python -B scripts/s07_contract_upgrade.py
```

## 框架边界

| 入口 | 行为 |

## 精确读迁移与 S05 兼容

`GET /api/v1/observations/current/` 的 `results[].input_version` 原位换为 64 位小写十六进制字符串。将其作为该会话和同一精确选择条件下的等值标记。保留获权的 `revision_id` 和 `rights_attributions`。无需迁移数据库中的业务主键。

| 旧读法或调用者 | 替代读法与核验 |
| --- | --- |
| `input_version.key` / `.revision`，`scripts/s04_checks.py:detail_http` 及复用它的 S05 运行器 | 用结果行的 `revision_id` 和产品、实体、时标、指标对账。通用明细有自己的 `key` / `revision`，独立 PG 键可用于验收。 |
| `input_version.qualification` | 公开读取依据为该行的资格状态和不透明标记。涉及内部资格版本的运维核验由受控领域审核完成。 |
| `input_version.rights`，`tests/test_observation_access.py` | 在真实 PG 核查撤权事件，HTTP 对照 display 拒绝和独立 analyze 权下的原修订及标记。 |
| `input_version.grants`，`tests/test_s04_selection.py` | 在受控 PG 核剩余依据，对外核 `rights_attributions` 和仅有该依据时的等值标记。 |
| `scripts/s02_disposition_checks.py`、`scripts/{s04_checks,s05_runtime_checks}.py`、`tests/{test_history_policy,test_s04_favorites}.py` 的整枚或整包比较 | 同格式继续比较，跨版先对账身份、修订、时标、值、署名和原 Session，再核新标记。 |

`rights_version`、`rights` 和 `grants` 的公开别名也被精确读 schema 拒绝。C02 回归验证权外变化稳定、权内变化可察、撤权拒绝及可信修订换标记。同值可信水位推进时，S05 研究输入可能换版，精确读在内容及资格未变时保持标记。

S05 研究响应顶层 `input_version`、`method_version=s05.v1`、`s05.csv.v1` 票据及 CSV 协议独立。研究游标、保存查询和升级前有效票据依原密钥与现权复核。研究请求使用精确读标记时返回 `409/input_changed`。真正变化的研究输入会使旧下钻和受影响票据返回 409。跨版本脚本用升级前实际签发的 Session、游标、保存查询和两张票据检查这些行为，并核对有效票据字节摘要。[票据申请与下载示例](#普通用户的-f-请求)
