## 宿主启动与静态目录切换

在 Linux / WSL2 使用项目锁定的 Python 3.13 和 uv。为目标实例准备独立 PostgreSQL 数据库与角色、Redis、实例标记和 `0600` 配置文件。需要 Beat 时先登记该实例的单一调度锁。配置字段、私有存储目录、`btree_gist` 和 PG/Redis 归属核对沿用 S07 宿主手册。常规本地实例保持 `CNEMC_MODE=off`，并关闭来源探测夹具开关。[S07 宿主手册 §§1–3](S07.md#1-准备独立实例)

在已有获准实例升级时，先按 S07 停复顺序退出旧写者。旧环境文件中的 `AQ_SPA_DIST` 应移除。将 `AQ_STATIC_ROOT` 指向实例根目录下一个新建的专用静态目录，和 PG、Redis、暂存、备份及签认目录分开。WhiteNoise 启动时索引当前静态根，向原目录再次执行普通 `collectstatic` 会留有旧 `app/` 文件。静态根切换后重新启动 Web，检查健康、Admin 和旧入口。原静态目录可按实例维护流程处置。[S07 停复顺序](S07.md#5-断网冷启与分组件恢复)

```sh
uv sync --locked
# 在同一实例的 Django 环境中执行。manage.py 从进程环境读取 POSTGRES_*、
# DJANGO_SECRET_KEY 和 AQ_STATIC_ROOT。main.py 从专用 0600 配置文件读取。
.venv/bin/python backend/manage.py check
.venv/bin/python backend/manage.py makemigrations --check --dry-run
.venv/bin/python backend/manage.py migrate --noinput
.venv/bin/python backend/manage.py collectstatic --noinput
.venv/bin/python main.py check --env-file "$AQ_HOST_CONFIG"
.venv/bin/python main.py web --env-file "$AQ_HOST_CONFIG"
```

独立 Web 负责查询、认证和 Admin。投递、导入和恢复等后台流程还需专用 Redis 与 Worker。需要整组时执行 `.venv/bin/python main.py --env-file "$AQ_HOST_CONFIG"`，沿用已登记实例的单 Beat。只启动 Web 时可以按实际需要使用 `web --dev`。端口使用已核对的回环 `WEB_PORT`。`GET /health/ready/` 返回 `200 {"web":"ok","pg":"ok"}` 表示 Web 可访问 PG，`503` 表示 PG 不可用。API 位于 `/api/v1/`，Admin 为 `/admin/`，静态资源为 `/static/admin/`。旧 `/`、`/app/`、深链及已清退资源在切换后应返回 404。[启动器](../../main.py) · [URLConf](../../backend/config/urls.py)

## 镜像与 Compose

`Dockerfile` 从 Python 镜像与 uv 构建，使用 `uv sync --locked` 固定依赖并在镜像内完成 Admin 静态归集。Web、迁移、Worker 和 Beat 共用该镜像。首次构建需要固定摘要的基础镜像和锁定包可用。预备好依赖缓存时，宿主可用 `uv sync --locked --offline`。镜像构建上下文只包含后端运行与验证输入。正式本地容器使用 `compose.yaml` 和 `compose.offline.yaml`，开发可以用基础 Compose 的 Django Web。启停、实例标记、双锁和环境变量见以下入口。[Dockerfile](../../Dockerfile) · [开发 Compose 和本地 F](../../README.md#原-s01-开发-compose-与-f-演示) · [正式离线 Compose](S07.md#4-compose-与-beat-切换)

## 隔离验证

从仓库根运行。所需本地工具按脚本分别包括 `.venv`、Docker、项目固定摘要的 PG/Redis 镜像、`bwrap` 与 Redis 服务端。运行器分配专用网络、库、Broker 和运行目录，验证归属后才写入 F，结束清理自有运行资源。核对收据的本轮源指纹、子步骤状态和 `cleanup`。

```sh
.venv/bin/python -B scripts/verify_s07_host.py r pytest
.venv/bin/python -B scripts/verify_s07_host.py restore
.venv/bin/python -B scripts/s08_contract_upgrade.py
.venv/bin/python -B scripts/verify_s07_host.py startup
.venv/bin/python -B scripts/verify_s07.py startup
.venv/bin/python -B scripts/verify_s07_host.py contract
.venv/bin/python -B scripts/s08_schedule_runtime.py boundary
.venv/bin/python -B scripts/verify_s07_host.py national-profile
.venv/bin/python -B scripts/verify_s07_host.py performance
```

普通回归与恢复专项各自给出节点和收据。升级脚本在停旧写者后的独立库应用四项 S08 迁移并重复迁移，验证旧 Session、游标、Job/Window、分析方案和 CSV。`national-profile` 在 51 城 F 上记录原投影、`home=1` 与筛选的 SQL/计划，以及五 Session 两波实际 Gunicorn HTTP，输出 `tmp/s07-evidence/<run>/V01/national-{legacy,home,filtered,http}.json`。`performance` 单独测量百万 F 的四个正式热 HTTP 预算。调度的 `pause-source` 和 `pause-product` 专项复核挂起、恢复和旧 Job 的独立控制。[运行器](../../scripts/verify_s07_host.py) · [全国剖析](../../scripts/s08_national_profile.py) · [调度运行验证](../../scripts/s08_schedule_runtime.py)

## 接入与当前门禁

后续客户端按同源 HTTP 接入运行中的 Django，读取 `openapi.v1.json` 的 55 路径、74 个显式操作。先引导 CSRF，使用 HttpOnly Session，登录后刷新 token，再用具名能力导航并按目标端点处理拒绝。私有数据禁缓存，失效、切域和撤权时清理现有状态及在途结果。分页、研究明细、导出与高影响写各自按游标、版本和原命令回执查账。展示字段、统计、缺口和许可采用服务端语义。[完整契约与调用样例](../api/v1.md) · [OpenAPI 3.1](../api/openapi.v1.json) · [S08 增强与兼容性](../verification/S08_CONTRACT_DELTA.md)

正式地图缺适用的地理资产、真实点位绑定及 CRS 核验。全国 API 的 `map` 当前返回 `unavailable`。获准的当期 H 还缺对应样本和用途。T11 为 **NO-GO**，前置包括适用来源用途、三地区跨发布周期证据及获权城市写读链，另需获准自然 168 小时试运行及正式复审。新正式前端尚未实施，当前双端联调与 S08 最终验收待完成，S09 尚未启动。[来源准入](CNEMC.md) · [总体实施方案](../design/总体实施方案.md#s08-正式前端与双端联调)
