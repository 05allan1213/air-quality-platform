# S08 前端运行与联调手册

正式应用由 Vue 前端、Django API 和原生 Django Admin 组成。开发入口是 Vite，宿主生产入口是 Gunicorn 和 WhiteNoise。两种入口的用户路径均为 `/app/`，API、Admin 和健康探针使用同一来源。实例标记、数据库、Redis、迁移和单 Beat 的准备步骤见 [S07 宿主启动与运维](S07.md)。

## 1. 准备依赖和专用实例

在 Linux 或 WSL2 的仓库根目录准备 Python 3.13.18、uv 0.13.6、Node 24.19.0 和 npm 12.0.2。Python 版本及依赖以 `.python-version`、`pyproject.toml`、`uv.lock` 为准，前端依赖以 `frontend/package-lock.json` 为准。需要离线复建时，提前准备对应操作系统和架构的缓存及所需镜像。

```sh
uv sync --locked
(cd frontend && npm ci && npm run typecheck && npm run lint && npm test)
```

已有 npm 缓存时，可在干净副本中执行 `npm ci --offline --no-audit --no-fund`。以退出码和安装前后的锁文件摘要验证结果。

S07 宿主守卫要求专用 PostgreSQL 库、Redis 实例和 `0700` 的 `AQ_HOST_ROOT`。从所选实例的 `0600` 配置文件读取 `AQ_INSTANCE_ID`、`POSTGRES_*`、`DJANGO_SECRET_KEY`、`CELERY_BROKER_URL` 和以下路径。配置文件支持 `--env-file` 或 `AQ_HOST_CONFIG`，默认位置为 `~/.config/air-quality-platform/backend.env`，设置 `XDG_CONFIG_HOME` 时以该目录为基准。将配置按 `KEY=value` 数据维护。准备业务库、标记和迁移后，使用 `python main.py check` 验证实例。[宿主配置校验](../../backend/config/host_config.py)

| 配置 | 用法 |
|---|---|
| `WEB_PORT`、`DJANGO_ALLOWED_HOSTS`、`COOKIE_SECURE` | `WEB_PORT` 默认 `8000`，Web 监听回环。回环 HTTP 用 `COOKIE_SECURE=0`，HTTPS 用 `1`。默认允许 `127.0.0.1,localhost`。 |
| `AQ_SPA_DIST` | Vite 构建输出和 Django 壳路径。默认 `frontend/dist`，显式路径使用同一个绝对目录。 |
| `AQ_STATIC_ROOT` | 宿主 `collectstatic` 目标，使用实例根内的独立目录。镜像默认 `/app/staticfiles`。与 SPA 构建、Broker、历史暂存及备份路径分开。 |
| `AQ_DEV_BACKEND` | Vite 开发代理目标，格式为 `http://127.0.0.1:<Web 端口>`。配置读取进程环境，对 `/api/`、`/admin/` 和 `/health/` 生效。 |
| `AQ_VITE_CACHE_DIR` | 可选。隔离工具将 Vite 缓存写入私有运行目录。 |
| `CNEMC_MODE`、`CNEMC_FIXTURE_HTTP`、`S03_FIXTURE_HTTP` | 宿主离线入口要求 `off`、`0`、`0`。 |
| `AQ_S08_FIXTURE_SCHEDULE` | 隔离浏览器工具为绑定到当轮 F 实例的 Web 注入配置专用开关。Worker 的值为 `0`。启用该开关的宿主入口拒绝启动 Beat。 |

## 2. 本机开发和生产入口

先生成前端构建和静态资源。`AQ_STATIC_ROOT` 和 `AQ_SPA_DIST` 使用专用配置中同样的路径。此处变量由操作者在终端设置，以项目根目录为工作目录。`collectstatic` 的进程使用仅供加载 Django settings 的占位值，和业务库连接配置分开。

```sh
export AQ_SPA_DIST="${AQ_SPA_DIST:-$(pwd -P)/frontend/dist}"
# 在终端设置与专用实例配置相同的 AQ_STATIC_ROOT 后执行
: "${AQ_STATIC_ROOT:?set AQ_STATIC_ROOT to the dedicated instance static directory}"
(cd frontend && npm run build)
env -i PATH="$PATH" LANG=C.UTF-8 \
  AQ_SPA_DIST="$AQ_SPA_DIST" AQ_STATIC_ROOT="$AQ_STATIC_ROOT" \
  DJANGO_SECRET_KEY=collectstatic-only POSTGRES_DB=unused POSTGRES_USER=unused \
  POSTGRES_PASSWORD=unused .venv/bin/python backend/manage.py collectstatic --noinput
```

- **开发**。在根目录开终端执行 `.venv/bin/python main.py web --dev`。另开终端执行 `cd frontend` 和 `AQ_DEV_BACKEND=http://127.0.0.1:8000 npm run dev -- --port 5173`。浏览器打开 `http://127.0.0.1:5173/app/`。Web 端口有变化时同步调整 `AQ_DEV_BACKEND`。[Vite 配置](../../frontend/vite.config.ts)
- **宿主生产**。在根目录执行 `.venv/bin/python main.py web`，浏览器打开 `http://127.0.0.1:8000/app/`。`main.py` 以 Gunicorn 提供本地 WSGI 服务。`/` 重定向至 `/app/`，SPA 深链的 GET/HEAD 读取构建目录内的 `index.html`。壳使用 ETag 和 `no-cache`，指向 `/static/app/assets/` 的哈希资源。`collectstatic` 收集 `assets` 和 `licenses`，WhiteNoise 提供静态文件。SPA 壳在 GET/HEAD 与 ETag 判断前检查构建 HTML 直接引用的入口脚本、样式和 `modulepreload`，逐项确认 `collectstatic` 结果可读。壳不可读、无入口脚本或直接依赖缺失时返回 `503` 和 `no-store`。修复时使用同一份构建重新执行 `collectstatic`，再启动对应 Web。[SPA 入口](../../backend/config/spa.py) · [Django 配置](../../backend/config/settings.py)
- **后台服务**。在已登记的目标实例上执行 `.venv/bin/python main.py worker`，消费 `s01.fixture,s02.history,s03.collection`。准备好 S07 排他锁与 Broker 登记后，才可在授权实例运行 `.venv/bin/python main.py beat`。`main.py` 默认的 `all` 同时请求三个组件，日常只选实际需要的组件。使用 `/health/ready/` 检查 Django 与 PostgreSQL 就绪，以获权运维页面检查组件心跳。[宿主服务入口](../../main.py) · [S07 服务与恢复](S07.md)

### 标签恢复、会话退出与待核命令

- 回到后台标签或进入另一工作区时，应用先隐藏私有内容，再读取当前会话和具名权限。若核验尚在进行时再次离开，再次返回会触发后续核验，期间私有内容持续隐藏。查询页和研究页在同一路由、账号和数据域重新获权后，可从内存恢复时段草稿或研究条件及原输入焦点。对象与所选研究系列经现行目录匹配，运行研究和提交查询仍需本人确认。条件草稿自开始核验起保留至多 30 秒，适合跨标签抄写时段。需要持久复访时请保存方案或使用带条件的地址。暂时无法核验时可点「重新核验」。工作区权限被撤回时可从拒绝页返回总览。
- 点击退出后，本机立刻清除私有视图。若退出请求显示失败，应用用 `/api/v1/me/` 核对服务端状态。`403/not_authenticated` 可确认退出。会话仍有效或核验失败时显示「退出尚未确认」，刷新和同源标签页继续受本机退出标记约束。共享设备上请使用「重新退出」并等到服务端确认。写入 `localStorage` 失败时，应用尝试使用仅含退出标记的同源 Cookie。跨标签页存储均不可用时，应用保留当前标签页暂锁。[会话状态](../../frontend/src/stores/session.ts)
- 采集、控制、重投、许可撤回结果待核时，回到同一会话的原工作区显式查询本人回执。采集命令需切回原数据域。原命令保存在当前页面应用的内存中，可跨站内导航。待核期间，相关写入口拒绝再次提交。本人回执表示受理或控制结果，实际运行状态在获权账本核对。[采集工作区](../../frontend/src/manage/CollectionLedger.vue) · [许可交接](../../frontend/src/manage/OperationsGrants.vue)

### Docker 镜像

`Dockerfile` 用锁定的 Node 构建层执行 `npm ci`、Vite build，Python 层执行 `uv sync --locked`、`collectstatic`，最终用户为 `app`。镜像内壳位于 `/app/frontend/dist/index.html`，静态资源和许可证位于 `/app/staticfiles/app/`。基准 `compose.yaml` 的 Web 命令使用 Django `runserver`，本手册的 Gunicorn 联调使用宿主生产入口。`.dockerignore` 放行应用和锁定构建输入，本机 `node_modules`、`dist`、`photo/`、环境配置和证据留在构建上下文外。[Dockerfile](../../Dockerfile) · [Compose](../../compose.yaml) · [构建上下文](../../.dockerignore)

静态复建可使用本轮独占且尚不存在的标签执行 `docker build --pull=false -t "$S08_IMAGE_TAG" .`。使用 `docker create --network=none "$S08_IMAGE_TAG" /bin/true` 创建检查容器，从其文件系统复制上述静态目录到一次性位置。核对 shell 引用、资源内容与许可文本后，按返回的容器 ID 删除该检查容器，并删除本轮标签。运行验证另按下一节使用专用实例。

## 3. 受守卫的隔离复验

从仓库根运行。工具要求已有 `.venv`、`frontend/node_modules`、固定的 PostgreSQL 镜像、本机 Docker、`bwrap` 与 Redis 服务端程序。浏览器模式还需要 `/opt/google/chrome/google-chrome`。`smoke` 和 `national-profile` 无需启动浏览器。[隔离工具](../../scripts/s08_browser_host.py)

```sh
.venv/bin/python -B scripts/s08_browser_host.py smoke
.venv/bin/python -B scripts/s08_browser_host.py dev e2e/monitor.spec.ts
.venv/bin/python -B scripts/s08_browser_host.py production e2e/auth.spec.ts e2e/scope.spec.ts
.venv/bin/python -B scripts/s08_browser_host.py production e2e/query.spec.ts
.venv/bin/python -B scripts/s08_browser_host.py production e2e/my-space.spec.ts
.venv/bin/python -B scripts/s08_browser_host.py production e2e/observation-chain.spec.ts e2e/favorite-rights.spec.ts
.venv/bin/python -B scripts/s08_browser_host.py production e2e/analysis.spec.ts e2e/quality.spec.ts
.venv/bin/python -B scripts/s08_browser_host.py governance-chain
.venv/bin/python -B scripts/s08_browser_host.py national-profile
.venv/bin/python -B scripts/s08_schedule_runtime.py boundary
.venv/bin/python -B scripts/s08_schedule_runtime.py pause-source
.venv/bin/python -B scripts/s08_schedule_runtime.py pause-product
.venv/bin/python -B scripts/s08_contract_upgrade.py
.venv/bin/python -B scripts/verify_s07_host.py contract
```

- `smoke` 检查基础服务、Session 和 F 查询。`dev` 经命名空间内的 `5173` Vite 代理。`production` 经 `8000` Gunicorn 和 WhiteNoise，核 shell、哈希资源和缓存，再运行 Playwright。工具会分配 `network:none` 的临时 PG 和独占 Unix socket Redis，生成 F 种子并启动独立 Web、Worker。运行前后核对实例标记、采集窗口、Run、发布次数及 Beat 脉冲。测试的 `S08_BASE_URL`、`S08_BROWSER_SEED_FILE`、`S08_EVIDENCE_DIR` 和 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 由工具注入。需要新空工作区的 spec 应各自运行，以免同轮私有方案和票据互相影响。
- `governance-chain` 使用正式壳，固定运行 `e2e/governance-chain.spec.ts`。隔离私网 F 源仅供本轮真正执行一次手工采集。浏览器核原信封、权限负例、账本和运维，Worker 和 PostgreSQL 核同一 Run、窗口、批次、回执及首次有效写入。该模式不接受选择器。[治理对账](../../scripts/s08_governance_browser.py)
- `national-profile` 使用同一隔离环境，对 F 全国同刻页做 legacy、首页和搜索路径的 SQL 诊断，以及五个真实会话的两轮 HTTP 计时。收据为当轮 `visual/national-{legacy,home,filtered,http}.json`。[性能脚本](../../scripts/s08_national_profile.py)
- `s08_schedule_runtime.py` 在独立 F/I 实例启动单 Beat 和 Worker。`boundary` 核跨交接、原 Run 重试和补采归属。`pause-source`、`pause-product` 分别核跨交接暂停、恢复及旧 Job 的独立控制。收据位于 `tmp/s07-evidence/<run>/V01/{result,schedule}.json`。[调度测试](../../scripts/s08_schedule_runtime.py)
- `s08_contract_upgrade.py` 在专用库从 `s07-backend-v1` 前向迁移，记录重复执行迁移和原对象、会话及票据兼容。`verify_s07_host.py contract` 运行隔离 V12 管理兼容检查。按收据的运行号和源码摘要核对候选版本。[升级脚本](../../scripts/s08_contract_upgrade.py) · [S08 增量 V12](../verification/S08_V12.json)
