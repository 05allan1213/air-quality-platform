## 4. 技术方案与契约

### 4.1 管理入口、事务与审计

沿用同源数据库 Session、CSRF 和 `policy.actor` 的具名权限。保留 `manage_collection/run_collection/import_history/review_observation/manage_grants` 的含义。拟增账号管理、质量裁决、目录治理、运行诊断、受控备份恢复等按职责分配的权限。能读审阅证据的人须另获裁决权。业务数据再过 `applicable` 的用途、受众、地域、对象、字段和数据期检查。Django superuser 仍走来源授权与 owner 过滤。`require_use` 目前对 `backup/restore` 无专属具名权限映射，恢复服务须同时显式检查操作员权限与来源用途。`s02_revoke_grant --actor` 的参数是受信主机上的归属标记，不能充当身份验证。新命令只消费由已认证管理主体签发、绑定目标/范围及期限的一次性操作号，执行前再查主体权限。后台 `dispose_due` 只执行 PG 已登记的法定待办，记录系统执行者与原动作，不由已卸任管理员取消必要处置。

| 受控权利/处置服务、恢复命令、`GET admin/operations/health/` | 来源配置仅允许有据的条款/范围变更，调用 `register_grant/revoke_grant`。处置和恢复以具名操作者、产品范围、演练目标标记和预演结果发起。健康 GET 只读有界状态 | 不接受任意 DSN、服务器文件路径、外源 URL、SQL 或请求正文作证据。读取健康和查询不投递采集任务。`/health/ready/` 保留匿名最小就绪契约 |

**C03 · S03 请求兼容矩阵（G2）。** 旧请求仅有 `action`。新请求另须带操作者选择的白名单 `reason_code`、客户端生成的 `request_id`（UUID）及受权 GET 取得的实际目标 `expected_version`（非负整数）。部分新字段、格式错误或未知字段均返回 `400 invalid_request`。Job 成功沿用 `200 {job, enabled, reason}`，Run 成功沿用 `202 {run_id, window_id}`。

| `action` | 旧请求 | 新请求的目标及锁内前提 |
|---|---|---|
| `pause` | 有权即接受紧急暂停。审计标旧协议、人工理由与客户端 UUID 留空，由服务端分配操作号。`operator_pause` 是 Job 状态码。已暂停时返回现状 | Job 版本及 `enabled/pause_reason`。新理由按实登记 |
| `resume` | 400，维持停用 | Job 版本及可恢复状态，复核 executor 和采集准入 |
| `resume_source` | 400，维持来源暂停 | 路径 Job 所属 **Source** 的版本、暂停状态及冷却截止 |
| `resume_product` | 400，维持产品暂停 | 路径 Job 所属 **Product** 的版本及暂停状态 |
| `redeliver` | 400，维持原 Run，无投递 | **Run** 的版本及 `pending/unsent/manual`、无 owner，核原窗口与执行资格。只投递原 Run |

目标版本在目标行锁下单调推进。人工控制和自动暂停同事务写 `ControlEvent`、版本和审计。Run 的普通状态变化在原任务事务更新版本。Source/Product 的版本由所有引用该对象的 Job 共用。`services.record_failure` 自动暂停（包括同原因的新事件或冷却变更）、`retention` 处置暂停和人工恢复均推进相应对象版本。单独暂停某个 Job 只改变该 Job。Job 的自动停用及 Run 的投递状态、次数、owner 或请求资格变化也须推进各自版本，状态往返仍能识别旧请求。记录发起 Job、实际目标和前后版本。旧行从明确初始版本开始。

先复核当前 Session、`manage_collection` 和该动作要求的用途/执行资格，再按 `(actor, request_id)` 查已提交结果。动作、路径 Job、实际目标、原因和预期版本全同，返回原成功码及获准的原收据，跳过再次变更、唤醒或投递。同号异参返回 `409 request_conflict`。新请求的目标版本或状态前提已变返回 `409 precondition_conflict`。权限已撤、会话已失效或用途不再成立时返回 403，连原成功收据也不披露。原有限速、冷却与配额拒绝继续生效。拒绝与回滚均不得产生成功审计或投递。

有业务影响的命令设一个操作 UUID。优先扩展现有 `ControlEvent` 记录任务动作，由一条最小治理审计记录连接账号、质量、许可及副本操作。事务内同时写被改对象、适用的 `Change/ControlEvent` 和审计结果，域 FK 可置空或随处置解除。审计仅收操作者内部 ID（自动事件标系统成因并关联 Run）、时间、目标类型及可保留范围、原因码、前后**状态码/版本**、处理结果和获准证据引用。处置完成记录只保留合法的来源、范围、时间、结果及必要计数。禁止请求体、自由文本原文、密码、Session 标识、测值、可逆 JSON 或未经准许的摘要进审计与日志。准入失败只回安全错误码，拒绝/冲突不能写成成功审计。

- **幂等和并发。** PG 对操作者和客户端请求号设唯一约束，动作随目标、前提进入参数比对。旧协议紧急暂停按上表处理。按 `clock_timestamp()` 在锁后及成功返回前复核权限、来源和期限。比较旧版本/状态后才提交。所有时间都带时区。
- **锁顺序。** 以现有 `admission.lock_job`、`research_session.lock_dependencies` 和 `reconcile_private` 为起点。共享目录先 Source，再按 PK 的 Product。采集分支沿 Job、WorkWindow、Run 及既有子项围栏，站点分支先 Station 再观测键。需跨多个来源/产品时先取全集、同类锁按 PK 排。上游锁之后才锁已存在的私有对象，再按 PK 锁所需 User、组和 Session。账号写事务只锁账号权限侧，避免持 User 再回取产品/私有行。新票据在锁定主体后插入。权限写入和高影响读写使用同一组锁协议，直接授权、组成员关系均在锁后重读，防止 `has_perm` 实例缓存穿过撤权。不同分支合并前以 V17 两种提交顺序实测。
- **账号停用、改密与复启。** 停用后下一请求须拒绝。撤回管理权限立即阻断对应操作，其他本人功能沿用原授权。改密沿用 `change_password` 注销与 Django 密码哈希校验。为防从未访问过的旧 Cookie 在复启后生效，建议用最小账号会话代次（一人一整数，按需创建），登录时绑定，停用时在 User 锁下推进。覆盖既有 Session 中间件、Admin 登录与 S05 `SessionCheck`。迁移前缺少代次的会话仅能匹配初始代次，复启需重新登录。登录与启停竞争也按提交时的活跃账号、代次和密码依据核对。

### 4.2 质量裁决、来源和时变身份

复用 `QualityIssue` 做事件主体。候选扩展为 `severity`、`status`、首次发现时刻/规则版本、处理人和最近裁决引用。沿用 `created_at/resolved_at`。已关联键的事件从键取内部身份和时槽，无键事件复用 `scope`（源地日期区间），有业务窗时补精确起止。已有 Batch/Receipt 能唯一回溯时沿用原 FK。解析早于 Batch 时允许直接指向 Run，字段被拒且只出 RunItem 时按需指向该子项。修订类动作记录**类型化**的旧/候选修订及资格版本，或指向能唯一确定该修订的 Receipt。禁止跨产品、跨 Run/Window/Batch、跨城站表或不唯一的血缘。约束可由 PG 检查/已有账本守卫与锁内跨表核对组合保证。产品级事件合法时 Run、子项、Batch、Receipt、Revision 均可为空。

分类覆盖缺项/缺测、无效单位与时窗、时间异常、重复、结构漂移、版本冲突、异常高值和身份不确定。可解释的重复沿用 Receipt，合法缺测沿用 Revision/RunItem。达到治理条件才建事件，避免每次读取都开单。建议严重度为 `info/warning/blocking`，分别对应仅记录、需复核、阻断相应可信输入或产品处理。工单从 `open` 到 `in_review` 再到 `resolved`，新证据可重开，历史未知严重度保持 `unknown`。认领或结案不直接改观测资格。缺口分别标为未获取、确认未发布/无此字段、字段无效、用途撤回或证据不足。将 `writer.manifest`、`write_cell` 与前置 `record_failure` 的固定错误映射到同一分类。无留存依据时只记录已允许的运行状态，不能为诊断持久化原包。按一次实际 Run/子项/分类/作用域或既有活动键和规则去重，重投幂等，不吞并另一真实运行或另一站址的问题。

| 输入 / 动作 | 可信状态变化 | 治理与下游 |
|---|---|---|
| `v1=10 → v3=10 → v2=20` | 一键一当前内容修订。v3 同值推进水位，v2 只留 `late` 事件/Receipt，仍为 10/v3 | 保留三次证据和同一个统计内容版本。v3 提交后，用 v1 精确版本下钻或领票返回 409。绑定 v3 的凭证不因 v2 迟到失效 |
| 同口径、可排序的可信异值新版 | 走 `apply_observation/decide` 保留旧修订，晋升新修订并发 `content_changed` | 受影响的实时统计重算，旧下钻/下载立即拒绝。`first`（含填补空槽）同样纳入影响范围 |
| 同版异值或无可信顺序异值 | 保留 candidate、`disputed`、`qualification_version` 和事件，默认 V 排除。抓取时间、操作者断言和包哈希均不能建立顺序 | 人工可认领、说明、保持隔离。结案与数据资格是两种状态，不能借 `resolved_at` 解锁统计。只有下列受信依据才允许解除 |
| 有争议后收到可信证据 | 服务端须证明同一键的**全部活动候选**均被同一受信排序或正式替代关系覆盖。同版异值须能判定哪次正式订正替代了冲突的各候选。覆盖不全时保持 `disputed`，即使新版已推进水位 | 解隔离时，裁决、资格版本与 `Change` 同事务提交，提交后重算可靠统计。实源目前无已核准的排序适配，保持争议。F 用登记的 `sequence` 验证 |
| 本站字段/单位映射修复 | 调 `correct_mapping`，从**仍获准留存及审阅**的原字段和登记规则重算。现成 F CO v2 可用。未知规则/旧水位/证据不符不晋升 | 同键标 `local_mapping_fix`。跨键用 `MappingLink`、旧键退休与新键版本。目标冲突时保留候选并隔离两端。与上游改报分开审计 |

**C04 · 裁决证据（G3）。** `evidence_ref` 仅接受服务端从该事件的获准证据中签发或列出的类型化标识。提交时重新解析血缘和用途。可用依据有两类。

- **来源订正**取自已登记的产品契约与适配规则。绑定来源/产品、逻辑键、排序方案与版本、来源 token、Receipt 及其 Revision。受信规则须能比较各候选，或能核对源方明确指出的替代关系。管理员给出的 URL、文件名、自由文本、哈希、抓取时刻和单独的 Receipt ID 均不能证明顺序。实际来源未核准此类规则时保持争议。
- **本站映射修复**绑定旧键、基准 Revision/水位、可合法复查的原字段、登记的旧/新规则版本及目标键。`correct_mapping` 用该规则重新计算，只处理能逐项解释的映射候选。成功记录 `local_mapping_fix` 与适用的 `MappingLink`，不据此解除独立的源方冲突。

现有 `decide` 可在 `disputed` 已为真时加入候选而不改 `qualification_version`。为此，审阅返回事件版本和候选集合。裁决在同一产品、观测键和相关 Issue 锁内，从 PG 重取当前修订及该键**跨批次、跨工单的全部未被有效裁决覆盖的候选**，逐项比对版本、候选 ID、证据、规则和水位。新增/移除候选、当前修订/水位/规则变动或有实质新证据时，写入方在同一事务推进所有受影响 Issue 的 `event_version`。工单处理状态变更也推进本单版本，纯重复收据不推进。审阅快照过期回 409，越权或未绑定证据拒绝且不改资格。只有实际资格改变才写相应资格变更。工单可结案且观测继续隔离。

来源变更沿 `Source/Product/UseGrant` 管理相应用途、契约版和生效时间。影响既有解释的规则变更必须定位旧/新规则覆盖的时槽，走映射或隔离流程。站点同码同址更名须有证据，保留 Station 并增有期限的 alias/名称记录。迁址调用 `catalog.relocate` 关闭旧 epoch 并创建新 epoch，旧观测仍关联原 epoch。同码复用不同站点须证实时段互斥，跨源同名保留独立。已跨越边界的旧观测走 `mapping_review_required`，禁止批量改外键。目录授权、站点锁、变更理由、前后范围和关联 `Change` 都纳入审计。收藏仍指向原身份。

### 4.3 哪些输出失效，怎样重算

治理变更用最小可保留描述定位影响。单键由 `Change` 与旧/新键导出产品、正式/F 域、实体/站址、指标、报告类型/时窗、标准系列、源日期或 `[start,end)`。站址/目录变更取受影响时期和共享来源下使用它的产品。撤权走 `UseGrant` 的 operation、audience、字段、地域/对象、数据日期和生效区间。映射须取旧、新两端的并集，新增时槽也查原来有缺口的查询。`changes_since` 对无键产品事件不能天然提供对象定位，须对本次作用域再投影。内部用该服务、QuerySpec、现有产品 M2M/目标 FK 及冻结的 `basis/groups` 缩小范围，再经现行授权关系精确核对。产品级 `rights_version` 单独变化不足以判定所有输出失效。跨产品取用途交集，未知范围标需复核。外部诊断只返回有权的窗口和受影响查询类型，私有标题、owner、票据号或具体意图只向本人公开。

| 实际消费端 | 变更提交后的行为与可验证结果 |
|---|---|
| `analysis/{compare,statistics,details}/`、S04 明细、收藏摘要 | 每次请求重建当前授权关系。`Relation.content_version` 反映统计内容/覆盖，`input_version` 还绑定精确键、修订、资格、水位及规则。旧 `input_version` 下钻应获 409，重取当前版本再按同条件对照有效支撑行。HTTP 保持 `private/no-store`。E/O/V、E共/P、75% 和相关性样本门槛沿用原服务 |
| `SavedQuery` | 保留本人查询意图。只在 `statistics_baseline` 留存权成立时保留基线，复访重鉴权重算，沿用 `current/data_changed/baseline_unavailable/method_changed/target_unavailable`。撤留存时清除有关基线、依据和目标关联，保留获准意图。不能用新计算覆盖用户原比较基准或抄存数值 |
| `ExportTicket` 和下载 | 授权变更沿 `reconcile_private` 按用途/受众/字段和冻结依赖作废、提前到期或清单删除。仅展示撤回时，确有独立导出与留存依据的票据仍可领取。纯数据变更按 S05 在领取时精确重算，**治理提交后的首次领取即拒绝旧版本**，无须批量改票。`download_export` 在同一事务锁依赖和票据，核 owner、Session、当前用途、C02 待核销范围、精确输入及投影，最后按 PG 时钟复核期限。只有持锁终检通过且事务成功提交才可发送内存 CSV。影响该票据的订正/撤权先提交，或下载事务回滚，均返回零 CSV 字节。下载先提交，该次已授权字节可送达，下一次须重新核验。保留 409 数据变更、403 用途、410 到期、清理或跨所有者 404 语义 |
| 文件、缓存、重算责任 | S05 不落地 CSV，已下载到用户设备的副本超出平台控制。请求级缓存和限流计数不含持久统计。数据库已有版本和 PG 即席查询即可验证失效。管理端给出可复查的产品/对象/窗口/规则及查询种类。演练由有权本人重访、重算或得到不可用。若日后新增受控派生物，须先登记依赖和清除方式。S06 不以新建 `Summary`、预生成文件或 Redis 结果库作为验收 |

### 4.4 留存处置、备份与隔离恢复

**处置起点。** `register_grant/revoke_grant` 在产品锁下变更权利并触发私有投影及 `DispositionJob`。业务读取先按 PG 当前时刻收紧。现有扫描 `dispose_due → reconcile_product → reconcile_data/reconcile_catalog/reconcile_private` 及 `collection.retention.reconcile` 核对扫描时的局部 deny、重叠 allow 与共享目录。P05 同时执行下文已固定的历史失权边界。数据日期和授权生效时刻是两条独立轴，现有 `data_from/data_until` 是来源本地**日**的半开区间，不能声称支持未建模的小时级授权。`retain_until` 或要求硬截止的限时留存目前在持久化边界拒绝。允许停机恢复后核销的 `valid_until + expiry_mode=recoverable` 到期即停止业务读取并补做实物处置。备份同样执行可兑现的期限，不能用轮询承诺关机时硬删除。

**C02 · 撤回生效至物理核销。** `reconcile_product` 目前按扫描时的 grants 清理。P05 在 `observations.disposition` 拟设 `loss_boundary(product, scope, fields, lineage, at)`，按输入血缘和 PG 时点给出待核销或已处置的交集。`policy.register_grant/revoke_grant` 在 Source/Product 锁下登记边界，各消费入口共用同一判定。在最后一项留存依据失效的事务内，扩展 `DispositionJob`，固定失效依据、生效时点、产品权利版本、对象/指标/字段/数据日期及覆盖的既存批次、修订或文件代次，不记测值。预登记的到期/deny 以 PG 时钟生效。新授权写入前先按原授权历史结算已到边界，读端也须识别已到期但 Worker 尚未扫描的范围。连续重叠的独立依据保全合法字段和对象，仅撤展示按 V10 处理。

| 领域入口（拟接入同一判定） | 对应的公共调用与断权时的行为 |
|---|---|
| `selection.ReadContext`、`queries.read_current/read_evidence/changes_since`、`analysis_query.build_relation`、`collection.queries.read_window` | 观测/目录/收藏、质量与运行审阅、统计及下钻，在选数、关联、计数和生成版本前排除命中的旧数据。其余获准范围照常投影 |
| `research_saved`、`research_exports.prepare/download_export`、受控文件打开、备份生成/发布和隔离恢复 | 复访重算只取合法输入。签票、领取和恢复均按冻结依赖复核，命中待核销旧输入时拒发该票据/相应分段，禁止先打开或物化受限文件。下载持锁终检、发布及恢复的最后一次核权均含此判定 |
| `revisions.ingest_batch/apply_observation/correct_mapping`、`history.stage_uci/consume`、`collection.writer.manifest/commit_chunk`、目录变更、缺口补采和质量裁决 | 在批次去重、读取原件、复用旧修订及提交新结果前核对范围和来源代次。重授不能使重试、导入、修复或重算复用旧数据。无法证明输入独立时拒绝，相交范围核销后方可接受独立获准的新批次 |

处置系统执行者经 `dispose_due → reconcile_product` 领取 PG 中已到期且未完成的待办。锁住待办和适用范围后，仅可定位、删行/清字段、关闭句柄、删除受控文件及核对残留，只输出获准的最小核销收据。公共 API、Admin、CLI 调用者均不能传入跳过判定的标志。重授不得取消待办。PG 变更回滚或任一受控件仍可打开时，待办保持未完成，业务断权持续。核销后按许可保留最小失效范围和版本边界，恢复时无法证明旧段未命中该边界即拒绝。V11/V12/V17 用实物缺失和合法对照验收。

| 载体 | 何时保留或清除 | 核销依据 |
|---|---|---|
| 规范化键、当前/历史/候选修订、Receipt、Batch、质量/Change、目录及运行账 | 仅展示权失效保留合法数据。撤去 `raw_field` 等可分离字段时，剥离全部修订原字段、locator、可选 metadata/JSON 和含整包信息的摘要。`REQUIRED={normalized,provenance}` 的原子组失去依据时，删除其受影响键和修订。产品、对象、指标、时期、目录及剩余合法投影分别对账 | 两个独立 SQL 视角核所有键/修订/候选/关联/JSON 字段，不能只查 current。混批不留原整批标识，另一获权对象仍可查询。混用字段无法安全表达时先禁收该形态，已持有样本须在期限内保全合法部分并核销旧载体 |
| 窗口证据、站址、意图、基线、清单 | 复用目录和账本清理、`reconcile_private/cleanup_expired`。已处置窗口不成为待补缺口，一次性额度不因删账重置。处置新增审计的明细引用，最小收据可独立存续 | 逐项核验残留 FK、历史数值/描述、摘要、可取 URL 和重新授予后的表现。合法查询意图与无关产品票据有正例 |
| 原始响应、H 暂存、受控副本 | HTTP 原包通常无留存权，仅允许已核明且有权的投影。若有获准的原件/受控文件，按 `retain_raw`/对应字段登记。H 的 `StagedInput`、Worker 私有 tmpfs 和 `clear_stage` 是现有文件边界。备份临时文件和最终包也在清册内 | 任务目录、UUID 文件名和白名单根，校验归属/权限，拒绝软链、越界、非任务卷。读取限于持有可终止的受控文件句柄的进程。处置先禁止新打开，再关闭/收回已有读取者，unlink 后复核目录项、打开句柄/旧链接与残留临时文件。未确认清除则保持待办、记录错误并重试。测试收据只留合法计数与状态 |

**备份单元与授权依据（G1）。** 本地使用有版本的**逻辑数据包**，在任务自有的 0700 目录按已授权的产品/对象/时段及可分离字段分段。用同一 PG 一致快照流式写固定白名单表/列（可用固定 `COPY (SELECT …)`），只打包本次可恢复的目录依赖、键、修订/资格/水位及确有权限的血缘。清单载明格式/迁移版本、源命名空间/产品、数据期、字段类别、依赖、签发时和最早截止。每段和必要完整性校验先满足 `backup` 及适用的规范化/原字段留存用途，有受控原件时另核 `retain_raw`。无法证明整包授权就拒绝生成。禁止复制共享 PG 卷、真实原包、整个 `.env` 或运行日志。审计、清单及摘要也受自身留存依据约束。

S06 恢复对象为上述获准的 PG **业务数据子集**及明确登记的受控文件，软件/迁移随已验源码重建。账号凭据/Session、第三方私有意图与导出票据、现行权利与撤回、配额/投递/租约、Beat 排程和待执行命令不从旧包激活。对这些运行控制事实，使用独立现行状态，无法重建时封闭相关功能，尤其不能产生新的来源试验额度。旧 Run/Receipt 只可在血缘、权利和不可执行性均可证明时作为历史恢复。依赖不完整的对象或整包拒绝导入。归属/外键转换按稳定来源命名空间、代码、实体有效期、逻辑键及包内关联验证，不能把旧整数 PK 当现行产品或授权标识。`Revision.actor`、`MappingLink.actor` 及历史 Run 的 actor/executor 等非空外键需要独立映射。清单只在获准时带可经包外证据核对的历史主体标识。导入锁定预先核准的一对一映射，链接目标库受控的历史主体（需要占位时用不可登录、无权限、无 Session 的隔离账号）。不搬运原密码、组或角色，也不把不同操作者统一填为恢复管理员。无权处理身份或无法唯一映射则拒绝依赖段。

1. **发布与撤回。** PG 以有限的副本清册行记任务 UUID、受控相对文件名、依法可保留的范围、最早截止和 `preparing/available/blocked/removed` 状态。沿用 `DispositionJob` 对账。开始生成时先在来源/产品锁下登记各段 `preparing` 及快照权利序号。失去唯一依据的撤回/到期必须同时封禁范围相交的 `preparing`、临时件和 `available` 段，之后重授不能撤销该标志。写入只使用不可访问的临时名。发布前重新取相同范围锁并核截止、当前用途、快照以来的撤回记录和准备状态。只允许同一轮且连续合法的段从 `preparing` 变为可取，发生断权的旧段和临时件必须核销。仍合法的兄弟段可独立发布。校验成功才原子更名并开放清册。打开副本也须复核，文件目录无静态下载挂载。PG 回滚、进程在更名/提交/删除之间退出、临时文件缺失等情形由启动/到期扫描比对 PG 与目录。孤儿永不发布，清理完成前不得记成功。
2. **失去留存/备份依据。** 先按当前权利禁止读取、创建和恢复，在适用期限内物理移除受影响分段、临时件和失效清单。混合包需要整份移除时优先由仍合法的现行资料在期限内另存获准部分，或在旧载体仍确有法定/许可依据时核验并拆出允许段。无继续保留依据的包立即处置，不能用隔离或等待重打包延长存期。优先在备份时分段并验证合法兄弟段可独立恢复，避免把唯一合法副本与待删数据捆绑。离线/找不到的介质标记未完成并升级处理，不能登记为已清除。演练只承诺核对受控存储实际可取的内容，不承诺擦除未知外部介质。
3. **C01 · 包外现行授权证明。** 权威来源是未回滚的业务 PG 中受控登记的 `UseGrant`、`Product.rights_version`、`Change` 和 C02 处置边界，以及具名授权保管人据原条款在**包外独立目录**保管的签发记录。恢复目标只有校验权。备份中的 grant、恢复操作者提供的公钥和旧库中的账号均不能签发现行授权。

   - **记录与顺序。** 每条记录绑定来源命名空间/产品、授权依据及条款版本、用途/受众、地域/对象/指标/字段、数据日期、授权起止/留存截止、动作及生效时点、签发主体/密钥标识。登记、deny、撤回、核销及重授在同一产品的提交序列中保留前序号和前条摘要。锚点记录起始权利版本和有据的历史范围。自然到期按已登记截止及 PG 时钟判断。历史链覆盖不到某段快照时拒绝该段。
   - **完整性。** 保管人对规范化记录和范围内的末序号、链摘要作本地签名。验签公钥与可信起点从备份目录之外的受控配置取得。按产品校验从锚点到当前版本的连续顺序、前条摘要、签发人资格和签名，再核分段清单、内容校验及依赖。缺项、断链、分叉、篡改、未知签发人均拒绝。材料仅保留获准的授权元数据。
   - **最新性与失联。** 备份发布、恢复导入前及一次性读取放行前，在同一来源/产品范围锁下从现行权威 PG 读取当前序号及到期/撤回状态，对照包外保管人的最新签认。签认绑定本次请求 UUID、具体动作、范围、末序号及链摘要、核验时刻和最早失效点。签名正确的旧记录也不能单独放行。包外记录落后、权威 PG 失联或可能回滚、证明缺失或期限已过，均关闭入口。预检失败不得物化数据，验证中失联则拒绝发布/读取并清理已暂存的自有行与文件。
4. **清洁恢复。** 先隔离文件并核验清单、完整性、来源身份、格式、截止和完整授权。仅在确认可临时处理/留存时才物化数据。使用空的同版测试 PG、专用无外网网络/卷/角色与文件根，隔断共享 DSN、Web、Broker、Worker/Beat 和所有在线源。按包外规则逐范围复核 `restore`、继续留存及处置/撤回历史，核对列、外键、修订状态、历史争议、目录时段和合法文件。被处置的旧版本不能因今天重新允许获取而复活。可独立验证的合法段导入干净目标，范围未知、依赖混杂、已撤范围无法排除或现行凭据不可得时拒绝，清除自有临时件。
5. **放行点。** 在目标仍隔离时做 PG 行/字段/版本、文件、权利、当前态及新登录 HTTP 对账。与权威来源同步互斥，复核最新授权/撤回序号和 PG 时钟。中途变更则重新裁剪或失败。放行限于**一次性演练读取**。恢复目标无常驻业务入口，runner 仅在持有任务自有权威源的相应范围锁且获得保管人确认的最新序号时，经私有回环 Web 允许一次新会话的验证读取，随后关闭读入口并销毁目标。权限检查、检查时钟和失联即关闭的闸门在隔离 Web 收数前生效，验证结束关闭闸门再释放锁。首次通过后再撤权或失去包外材料时，后续请求必须被拒绝，自有文件和暂存行也须核销。超时/进程退出保持隔离并进入恢复清理。S06 只验合法业务子集。整机灾难恢复、权威库丢失后的接管和常驻切换均在本阶段之外。

### 4.5 运行健康和失败定位

公开 `/health/ready/` 保留现有 Web/PG 返回码。受限管理读端按组件给出 `state, observed_at, evidence_kind, valid_until, reason_code`。服务证据过期、探针未部署、观测位置无法区分故障时均给 `unknown`。探针要有时间上限，诊断请求不访问实源。PG 已断时，依赖 Session 的管理 API 可以安全返回 503，运维从回环 readiness 和本机探针读各自结果。

| 分项 | 采样依据 | 能够下的判断 |
|---|---|---|
| Web / PG / Redis | 回环 HTTP 实际响应和状态码、应用身份 `SELECT 1`、同项目同 broker 有界 `PING`，分别记录时刻 | 请求失败按所在探测点报告。PG 失败可同时观测到 Web 返回 503。Redis 不可达提示投递异常，已有 PG 查询单独核验 |
| Worker / Beat | Worker 对预期节点和队列的有时限探测，结合其自身心跳、消费或最近有效执行。Beat 用唯一调度器在**自身完成调度 tick** 后定期更新最后证据，独立于 Worker。如需持久化，仅保留每组件/实例一条短期心跳与过期时间 | 管理 GET 读取探测结果。区分“进程可达”和“指定队列完成过消费”。零消息、Redis 可达、历史 `last_run_at` 各自都不足以证明两个进程健康。建议演练用 10 秒采样、30 秒有效期，按假时钟单测并在独立进程实测过期 |
| 积压、窗口和来源 | 查 PG `pending`、`dispatch`、`dispatch_due`、`next_retry_at`、配额等待、执行中及最老年龄。可选有界采样 Redis 指定队列长度并注明只含 ready 消息。`Run.request_state=possible` 保守计费。Run 结果、窗口认可和当前 V 从原账读取 | 区分来源/传输故障、合法响应但本次无新发布、结构暂停、配额/权限暂停、部分成功、证据不足。`no_new` 是在该次响应范围内未见新发布。对上游长期停更的判定需要独立节奏证据 |
| 受影响查询 | 从 `Run.window` 查 Job、同窗尝试、可见 RunItem、`Run.batch`、`Receipt.collection_item`、修订和 Issue，缺的关联显式为空。对混合窗口复用 `read_window` 的作用域投影。用范围构造受权的 S04 查询/研究条件 | 管理员只见授权内的影响。用户从 `observations/query/` 的 `latest_valid` 或城市/站点详情读获准旧值，返回真实 `observed_at`、可证的 `fetched_at`、年龄和来源状态。C 仍为同刻七槽，明确历史窗不得回填。可见数据与新鲜度不足分开表达 |

P1 趋势从现有账本按产品、已授权对象和固定时间桶聚合。任务等待为 `started_at−created_at`，排期偏差用 `scheduled_for`，执行时长为 `finished_at−started_at`，缺任一端报未知。分别列终态尝试数、确认响应数、含首次观测的窗口数、独立业务窗口数、部分窗口及失败数。每个成功率带分子、分母、区间和纳入的状态。重投不增加应有窗口，`partial` 中的首次认可可计新观测。质量覆盖取独立格 E/O/V，未知 E 不给比例，跨对象研究沿 S05 的 E共/P。数据年龄用观测时刻，只有来源提供可靠发布时刻才计算发布时延。

## 6. 测试设计（执行权限在后续实施阶段）

**证据与隔离。** F 为有明确本地用途的自制输入，I 为在该任务资源内注入的故障，H 为重新核验实际用途、署名和保存条件的本地许可历史输入。R 为单独获准的真实来源。S06 不需要实源访问，既有 A03 仅作 R 历史说明。UCI V16 的短期研究授权不能照抄。以 F 的可识别哨兵检查泄漏，只在自有环境取证。H 只保存有权的聚合和署名。任何新用途权利不明时按拒绝取证。

- 规则层用纯测试覆盖分类、半开区间、重叠授权、影响相交、状态迁移与版本判定的输入表。PG 层采用 pytest-django 真实事务、独立连接、唯一/排斥/FK 约束和 SQL 手算。HTTP 层使用两个主体、独立 Cookie jar、真实登录/CSRF、失败码、响应体和数据库对照。每种证据分别标识。
- runner 参考 `verify_s05.ensure_owner` 的本机 Docker、随机标签、`network=none` PG、私有 Unix socket、临时凭据和数据库运行标记。需要跨进程网络时用 `scripts/s03_compose.yaml` 的**独立** internal 网络、内部 F origin、受测源码构建的 Web、Worker 和唯一 Beat，加任务自有 Redis/队列。运行节点、心跳与数据库名字均带本轮 ID。断开/杀进程前二次核对归属。备份、恢复用互不共用的自有工作目录与空库，启动时无外源、无共享卷和默认 `.env` 凭据。执行前后核对共享项目及运行器资源归属。
- 每项收据拟写 `tmp/s06-evidence/<run-id>/Vxx/` 下的脱敏 `expected/actual`、SQL 计数、HTTP 状态/安全字段、PG 时刻与跨度、进程/队列信息、文件核销及 cleanup 结果。随机密钥、Cookie、原包、无权数据和任意备份本体排除在证据包外。**PASS** 须满足该行全部断言和证据类型，任一违反为 **FAIL**。未执行或缺依赖为 **NOT RUN** 并写明原因。P0 所需证据遗漏时不得封版。
