## 3. 领域契约与正确性约束

### 3.1 来源、产品与用途

在一个新的 Django app `backend/observations/` 内建设。`Source` 记录发布者、稳定命名空间。`Product` 外键指向来源，`UNIQUE(source, product_code)`。记录产品族 L/C/S/T/D/H/F、实体层级、指标/窗口契约版本、证据、可回溯范围。H 的产品码绑定 UCI 数据集 501。正式 F 反例属于专用 `test.s02.*` 来源，产品族固定 F、`synthetic=true`，可分别模拟 L、C、T、D 或 S 的字段形状。PG CHECK 固定 F 的合成标记和 H 的站点层级，写入服务再按产品限制目标表。目录记录和实际操作许可分别建立。

`UseGrant` 每行描述一个产品的一项用途，带受众、地域/对象范围、适用数据时段、条款出处与版本、署名和限制、确认人、操作生效/终止时间、撤回时间/理由。分别表达数据留存期限、配额/频率、允许的字段与证据形态。操作有效期用 `[from, until)` 判断，历史样本覆盖日期与**今天能否使用**各查一次。条款修正保留版本，以受控服务登记生效/撤回。迁移完成时没有自动放行的正式用途。

| 检查边界 | 独立用途及判定 |
|---|---|
| 准备 H 文件、提交任务与 Worker 打开文件 | `acquire_file`（在线自动获取另列）、`process_local`、`retain_normalized`。暂存整个包另查 `retain_raw` 对**整包地域、时期及期限**是否适用。三处各按当前身份重查。 |
| 即将入库 | 对每个产品/地域、数据时段、受众和拟留存字段重新判 `retain_normalized`。原包/原行留存、原字段和追溯证据的保存依具体依据。只能留规范值时，禁止可还原原包的转存。连最小溯源要求也无法满足时拒收。 |
| 读取与溯源 | 本地登录展示、公开展示、内部分析、治理查看分别判定。查询条件从服务端解析用户、产品与对象，原值/候选的展示须有相应字段和受众依据。 |
| 下游预留 | 截图传播、原始/汇总导出、再分发（含入库仓/打包）、备份、恢复分别登记。交付时只开放实际有实现且已核准的用途。多源操作取各输入授权交集。 |

`require_use(actor, product, operation, scope, data_window, fields)` 返回本次有效依据的 ID/版本和最早截止时间，缺项、未确认、超范围、已撤回或到期一律拒绝。平台内部服务账号也限定操作。确有独立合法依据时可继续该范围的留存，冲突条款先拒绝待核。S02 采用同产品行作为共同锁点，授权变更/新增、写入、读取和处置采取同一顺序。取得锁后重新读取活动账号、具名权限和当前许可，以数据库 `clock_timestamp()` 判时。长事务在写成批次成功前再次查时限。查询在锁内完成权限检查和序列化。已在撤回前完成授权的响应与撤回后新请求分别取证。读端的受众与留存服务的受众分别匹配。S01 的 F 策略不回退到正式策略，正式策略也不读取 `FixtureGrant`。

### 3.2 城市、站点和站址期

`City`、`Station` 用内部稳定 ID。来源代码和有据可查的别名按类型分开，`CityIdentifier`/`StationIdentifier` 记录命名空间、原码或别名、实体外键、有效区间和证据。有效期内一个来源代码只绑定一个实体，异源同名保持独立。同码有证据的更名追加别名，站码被重新分配时建立新身份及互斥的代码有效期。保留原文本和前导零，城市异常码如 `0` 拒绝建成真实城市。别名可以重名，自动解析只使用明确代码/数据集内部标识。

`SiteEpoch(station, city, active_period, location_evidence, name, coordinates?, crs?, certainty)` 保存 `[start,end)`。PG 用 `tstzrange`、非空且下界确定的区间约束，以及 `EXCLUDE USING gist (station_id WITH =, active_period WITH &&)` 防止并发重叠。代码类型另加 `(namespace WITH =, code WITH =, active_period WITH &&)` 排斥约束，两类区间均用 CHECK 固定左闭右开且有序。先用 Django `RunSQL` 执行 `CREATE EXTENSION IF NOT EXISTS btree_gist`（反向 `RunSQL.noop`），再建表并添加 `ExclusionConstraint`。迁址时同事务关闭旧期并开新期。旧时刻仍引用原 `SiteEpoch`。已知统计窗口横跨迁址时隔离，标签型观测按原时标选期。缺期、归属不明或多解留产品级质量事件。修改会改写已有观测归属的区间须经有证据的映射修订。

UCI 的 `station` 字段按 `uci.501` 命名空间生成数据集内部 ID，城市依据为该数据集明确的北京范围。用文件可证实的报告时段建**数据集报告身份段**，标记实际站址沿革未知。经纬度、坐标系和官方站码留空。迁址反例在可控 F 中给出两段有明确依据的地址期。

### 3.3 观测键、内容修订和血缘

采用**逐指标长记录**。一个站点小时的六个 H 字段对应六个逻辑键，同一键的多次读取仍只算一个。`CityObservation` 指向 `City`，`StationObservation` 指向 `SiteEpoch`，两张表分别存身份与水位。各有对应的 `CityRevision`/`StationRevision` 存实际值与状态，共用 Python 字段定义和同一裁决函数。物理分表使站点修订无法挂在城市观测上，也无需多态外键或跨表当前指针。

| 对象 | PG 保证 | 服务负责 |
|---|---|---|
| 两侧的逻辑键 | 每侧以 `(product_id, city_id 或 site_epoch_id, indicator, report_kind, window_definition, standard_series, 时间锚)` 唯一。日产品用 `local_report_date`，其余用 `observed_at_utc`，CHECK 恰一非空，按两类建立条件唯一约束，其他键列 NOT NULL。小时记录仍另存 `source_local_date`。本阶段的固定窗口定义包含周期/长度、标签含义及口径，已知区间须与时间锚相符。 | 验证产品允许的层级/指标、对象来源、窗口、归属时刻与标准。未纳入产品契约的可变窗口隔离，待可证明其唯一身份后接入。未知标准给产品内明确的未知系列，浓度的 AQI `not_applicable` 与未知 AQI 分开。 |
| 内容修订与当前记录 | 各修订 FK 只指向对应键，`UNIQUE(key, revision_no)`，`UNIQUE(key) WHERE is_current`，候选不能为 current。内容只追加，晋升仅切换当前标记。数值状态和单位有 CHECK，删失限制值/方向单列。按产品、实体/期、指标、时标建读索引。 | 规范内容按值、规范单位、状态、删失边界及有业务含义的源描述逐字段比较。Decimal 表示等价、JSON 顺序或抓取时间变化不生成新版。非有限数、单位错误走质量分支。只有当前、无未决争议、质量有效的数值进入可靠选择。 |
| 观测水位与批次 | 键上单独保存 `trusted_scheme/token` 和对应证据引用，修订保存处理规则版本/种类。`Batch` 记录产品、来源材料身份、选择范围及时间，`ImportAttempt` 记录提交人、原因和执行结果。 | `Receipt` 关联批次、类型明确的键/修订、行定位和裁决结果，能追到首次、重放、同值推进、迟到和争议。使用双可空 FK 时加 XOR CHECK。一次读取证据的唯一范围为批次、字段定位、规则版本，稳定动作重复执行只复用证据。 |
| 质量与影响 | `QualityIssue` 必有产品，批次/键可选，最多关联一侧。`Change` 在同一 PG 事务登记产品、对象/期、时间窗、原因与变更版本。只保存获准的证据。 | 结构漂移可在无行时留事件。记录规则/版本、发现时间、处置人/依据。受影响查询的输入标识由键、内容修订、质量/争议资格版本和当前授权范围版本组成。 |

产品层级、地域和站址归属在写入前核对，原始时间/单位不可解释的行即使携带较大版本号，也只能进入隔离证据，不能推进水位。来源明确报出的缺测可有键和状态，完全没有源行时没有观测键。之后的 O 和 V 可分别复算。当前内容可以是已确认的缺测，默认可靠值读取便为空，不能回退取旧值。晋升、水位、争议标记、质量事件、影响记录与批次对账一致提交。小样先锁产品，再按稳定顺序锁批次和键，初创键依靠唯一约束及冲突后重读，禁止用无锁的“先查后插”判幂等。

### 3.4 标准化和质量输入

`normalize(product_profile, raw_record, batch_context) -> normalized_fields / issues` 是纯规则入口。文件适配负责 CSV 列与行定位，未来 HTTPX 适配只交候选字段与来源证据。`ingest_batch(actor, batch_identity, product, candidates)` 为 H 小批量提供外层事务并完成对账。其内部 `apply_observation(context, candidate)` 在调用方的 PG 事务内复核用途、解析身份和裁决，返回键、当前修订、来源水位、处理分类、问题/变更 ID。S03 可在同一事务追加子项回执，两者一并提交。S04 可调用 `read_current(actor, exact_selector, purpose)` 复用产品、用途、时间和可靠资格筛选。客户端无权指定可信排序方案、合成标志、城市官值身份或当前版本。

| 字段组 | 处理与可核对输出 |
|---|---|
| 三类时刻 | 保存原始时标文本/年月日时、来源时区及其依据、UTC 观测标签和地方日期。获取时间记录实际读取该源文件/响应的时刻，已知的文件取得时刻分列。执行开始/结束在 Attempt 上。源方发布时间仅有依据时写入。 |

## 4. T06 裁决表与失效接口

在同键行锁内比较。`compare_source(incoming, watermark)` 只接受产品约定的、同一顺序域内可验证的来源序号或源方版本证据，返回 `older/equal/newer/unordered`。F 用受控的数值序号测试，包括 v2 与 v10。UCI 的 `No` 是行号，ZIP 指纹是文件校验，获取/执行时间是本站时间，三者均不提供源方先后顺序。规范内容摘要只加速相等判断，最终比较规范字段。

| 输入和前提 | 键、当前内容、水位 | 审计、资格和对外影响 |
|---|---|---|
| 首次可接收 | 建一键和初始内容。可信版本设初始水位，H 可保留未排序的首个无争议内容 | 留首次收据。具备基本质量和用途条件的字段可读。 |
| 1. 同键同内容重放 | 同版本或无新顺序证据时，键数、内容修订、水位均不变 | 新批次可登记重复读取。同一已成功批次再投只增加相应尝试事实。 |
| 2. 可信新版、同内容 | 水位和最新来源证据推进，沿用原内容修订 | 记 `watermark_advanced`。含义、质量资格和权利未变，无须使统计输入失效。 |
| 3. 可信新版、异内容 | 先保留旧修订，再晋升新内容并推进水位。旧值可追溯 | 原子写 `content_changed` 和受影响范围。若新版明确缺测，当前可靠数值即为空。 |
| 4. 旧版迟到 | 先比较来源水位，即使内容相同也保留迟到分类。键数、当前内容、水位不变 | 记迟到 token、比较依据、批次和原因。迟到本身不重开当前争议。 |
| 5. 同版异值 | 持久化非当前争议候选，保留最后无争议内容及既有水位 | `same_version_conflict` 关联双方证据，置未决争议。当前可靠选择排除该键，治理端可标明最后无争议值。 |
| 6. 无可信顺序、异值 | 同样隔离候选，保留既有指针和水位。若原为无序首值，新到有版本的异值也需有二者关系的证据才能晋升 | `unordered_conflict`，含无法确立比较域的原因。相同候选重复读取复用候选和活动事件。未决争议的开启/解除均改变可靠选择资格。 |
| 7. 本站解析/单位映射纠错 | 专用 `correct_mapping` 指定键和所依据的修订、水位、规则及获准原字段。在锁内核对仍为目标当前版本，过时证据转待核。内容变化建 `local_mapping_fix`，处理规则与源方水位分别保存 | 记录操作者、理由、旧/新规则和影响范围。退役映射的重放不得覆盖修复。若纠错改变逻辑键，原子标记旧键退出可靠选择、关联正确新键并记录两边的影响。目标键已有不相容值时转争议。 |

无水位时，若可信输入与最后无争议内容相同，可登记首个水位并沿用该内容。纠错需要可合法复核的原字段或获准重读的等价证据，缺依据保留待核状态。

最小验收序列为 **`v1=10 → v3=10 → v2=20`**。三次读取后 `(逻辑键数, 当前可靠数, 当前值, 水位, 已确认内容修订总数, 迟到事件数) = (1, 1, 10, v3, 1, 1)`，v3 的推进收据可查，v2 不能成为当前。另起键分别验证新版改值与两种争议。已有争议的普通重放不能解除争议，需有据的裁决/映射修复并保留处置记录。

`input_version(key, use_scope)` 输出内容修订、资格版本和授权版本，读取时另核实实际期限。`changes_since(id, product, scope)` 使用单产品游标，事件与业务写入持同一产品锁提交。从 PG 给出事件号、改变类型、键/范围和版本，不含受限测值。来源订正、本站修复、争议导致资格变化、授权变化及处置在提交时即对新读取可见。水位单独推进可供审计，但内容依赖标识保持稳定。S05 把真实统计输入和导出件绑定这些版本，生成/下载时复核。S06 接入重算、撤回与备份，S07 复验整条 T06。S02 验收检查已存在的选择结果、事件和版本标识，不制造占位汇总、缓存或导出文件。

### 5.3 文件到事务的执行路径

1. **准备。** 受信本地维护命令显式登记 UCI 依据及本次地域、时段、受众、原文件临时留存期限、规范值与展示用途。已有获准文件可完全离线重放。初次获取时先核用途，再由操作者从上述 UCI 直达地址取得原包，校验 SHA-256。操作者先验原包权限。在 Worker 容器内用受信本地命令 `s02_stage_uci` 从标准输入接收获准的字节。挂载只供该 Worker 使用的有界 tmpfs，限制为应用 UID 可读写。命令按产品锁复核整包获取、处理和临时原文保存依据，先登记带所有者、期限及随机 `stage_id` 的 `StagedInput`，再限量写入 Worker 私有 tmpfs 暂存目录。只把完成校验的文件标为可用，遗留半成品按登记 ID 清理。只读打开文件的导入代码和有权解除文件链接的处置代码共用这一目录。操作者原件不挂给应用，仓库和镜像不分发数据包。香港样本、CNEMC 回执均排除。
2. **认领。** 已登录且有 `observations.import_history` 的管理员提交固定 profile、所属授权范围内的 `stage_id` 和受限理由。创建 `ImportAttempt`，事务提交后向同一 Worker 的新本地队列投递 UUID。保留 `s01.fixture` 监听和单 Beat。队列无测值、路径或 URL。Worker 再判操作者、用途、文件范围和受控暂存 ID 后才以只读方式打开包。拒绝任意路径/URL/上传，Worker 继续只接内部网络。投递未确认给出尝试号，按号检查、受控重投。S02 无通用窗口账本。
3. **预检。** 标准库 `zipfile/csv/decimal/zoneinfo`。先验允许的正规文件、路径所有权、归档 SHA 和尺寸，再按准确名单逐个流读。输入上限建议 9 MiB，展开总量 40 MiB、单成员 4 MiB，限 12 个 CSV 和一个目录，每站最多 35,064 数据行，限制字段长度和实际读取字节。拒绝路径穿越/绝对路径、符号链接、重复名、加密、意外嵌套/成员、CRC 错误、坏编码和畸形 CSV。禁止解包到任意路径。逐文件验证头、站名/逐行 `No`、唯一小时标签、合法年月日时、实际首尾、总数、字段状态和单位。只有获准的选中段留在有界内存中。文件变更或缺少许可时停止，差异待查，不自动换用新版。
4. **入库。** `Batch` 的唯一身份为产品、许可允许的文件身份（该 H 为 SHA-256）、版本化的选择清单（站点、窗口、指标），不含触发人、执行时刻或源版本猜测。记录身份解析/映射版本，升级映射走 §4 的纠错路径。文件预检与观测提交分段，每段在产品锁内核对该段用途。正式写事务使用已验证字节的有界选样，重新查当前授权及身份段。提交事务按产品 → 尝试/批次 → 观测键的顺序上锁。小样在一个 PG 事务中写键/修订、收据、问题、影响和成功批次。相同字节/选择清单重导、同 UUID 重投、并发首导均只有一套观测。独立请求使用各自受控暂存 ID，留各自尝试结果。已终结的同一 UUID 走终态核对，无需重新打开已清除的临时文件。同源不同选择清单即使时间相交也复用相同逻辑键。
5. **失败与交付。** 格式级错误整批拒绝。可定位的单项缺测、删失及可疑值按质量状态提交，列出数量。PG 写到中途失败时整体回滚，外层在 PG 可用时只记失败尝试/允许的最小原因，若前次暂存件已清除，可在重新授权后重新暂存同一归档，按相同批次身份重试。成功、拒绝、中断均由文件所有者清除临时副本，异常退出由到期处置复核。完整输入缺失的 H 验收记 BLOCKED，纯规则和 F 证据可分别记录。

## 6. 最小读端、撤权和本阶段实际处置

- `POST /api/v1/admin/history-imports/` 接受 `{profile, stage_id, reason}`，actor 取活动 Session。控量、限速、CSRF 与命名权限先于投递。成功 `202 + attempt_id`，未确认 `503 + attempt_id`。治理改权和映射纠错走受控服务/本地管理命令，记录可信维护者或真实请求身份、理由和依据。高影响模型不挂 Admin 通用 CRUD。
- `GET /api/v1/observations/current/` 接受单一产品、城市或站址期、指标、窗口、标准系列和精确 UTC 标签或地方报告日。服务端同时检查平台对此数据形态的当前留存依据和用户的展示依据。处置待办期间仍然拒读已失留存依据的部分。按已授权产品和对象做数据库过滤并选择当前可靠内容，每次最多一键。返回当前修订、来源、合成标志、时间/时区依据、单位、质量及适用署名。获权空窗、缺测或争议可返回 `200` 空结果及适用原因。无展示权或不明用途统一 `403/use_denied`，不泄露值、计数、候选、时间范围或存在性，匿名 `403/not_authenticated`，错参数 `400`。`Cache-Control: private, no-store`。真实读取入口限定非合成产品，另用显式 `scope=synthetic` 在有权的 F 空间演练。
- `GET /api/v1/admin/observation-evidence/` 按一个批次或一个类型明确的键查修订/候选、当前水位证据、质量状态和批次收据，需 `observations.review_observation` 和当前治理用途/字段权。按请求产品与地域在数据库中过滤后投影，上限 100，超限给稳定继续位置。无行的产品/批次事件也可核查。普通用户和跨域 ID 猜测都不能读候选。
- `change_grant(...)`/`dispose_due(...)` 以产品为锁点。仅失去展示权时立即禁展示并改变该用途版本，核对仍然适用的保存/内部分析依据。仅失去其中一份留存依据时逐地域、对象、日期和字段重判**其他独立有效依据**。没有依据的部分执行本地受控删除，若依据明确指定其他处置方式须验证其不可还原性/适用性后采用。受影响键、所有当前/历史/候选、原值、收据、可还原的摘要/哈希、事件详情和临时原包均纳入清单。混合批次按行处理，整包无完整保存依据时清掉整包，保全仍获准的规范子集。最小处置审计只留许可允许的来源、范围、时间、结果等，不能反推数值。
- 主动撤回由 Worker 容器内受信本地命令调用，能同时核对 PG 和所辖暂存目录。立即提交权限失效标记，然后执行处置，核对完成后才返回处置成功。期限型许可在生效时登记截止日，在同一 PG 事务登记 `ClockedSchedule`/`PeriodicTask(one_off=True)`，使用已有唯一 Beat 的**一次性本地处置**投递到 `s02.history`，由同一 Worker 处理，也提供本地 `dispose_due` 复跑入口。按依据预留提前执行窗口，短期限或离线期间无法保证处置时拒绝此类保存或提前清除。读写入口按真实截止时刻即刻拒绝，启动/恢复入口先清查已到期记录。文件清理与 PG 无共同事务，保存不含测值的待处置标记、阻断受限操作、幂等重试，由所有者核实路径已清除后才记完成。有权只读的操作者原件与平台受控暂存副本分别列明。暂存/处置入口还需处理 Worker 重建后 tmpfs 已清空的情况，核实指定文件确已消失再结清其处置记录。默认迁移不启用业务周期项。S06 将同一处置协议扩到届时的汇总、可下载副本与备份，并在隔离恢复前检查备份外的当前许可/撤回记录。
