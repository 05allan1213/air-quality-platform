## 4. 架构与接口方案

### 4.1 同一份查询条件，从结果回到明细

沿用 Django 单体、数据库 Session 和 PostgreSQL。在 `observations` 内把条件解析、用途判定、获准的时槽关系和结果投影分开。比较、统计、下钻、CSV 及复访都调用这个服务。已有 S04 URL 保持原契约，S05 不通过循环发送 HTTP 请求或拼接 S04 页面实现聚合。

`QuerySpec` 为服务端校验和规范化后的条件。保存来源 namespace、确切 product ID、正式/F 域、层级、有序对象 ID（城市或站址期）、指标及各自的单位/标准系列（`standard_series`）、`report_kind/window_definition`、质量策略、显式 `[start,end)` 与来源时区、桶粒度、方法/版本、稳定排序。A−B 的对象顺序属于条件，不能照搬 `detail.sequence()` 的排序去重。重复对象、同一站点的两个期冒充两个站、未知字段、隐式换源、客户端自报受众/算法表达式均拒绝。时间输入必须带偏移。按 UTC 时刻对齐，按产品登记的源地方日分桶，并随结果标明时区证据或假设。比较和研究统计限 C/S/H 及其 F 形状。明细下载可承接 S04 已能表达且取得相应用途的单产品条件，L 的 `*Level` 保持等级，T 保持近期趋势，D 地方日报沿用独立精确查询和准入。固定锚加跨度在创建时解析为绝对窗，回访/下载沿用同一窗口。最近有效仍走 S04 明确的模式。

**拟议 HTTP 契约**。所有路径以 `/api/v1/` 为前缀。结果都带 `Cache-Control: private, no-store`。采用同源 Session，POST/PATCH/DELETE 校验 CSRF，服务端解析 owner。查询 POST 仅为传递有界结构化条件。

### 4.2 用途、受众和资源边界

**C01 · 登记与判定使用同一对照表。** `policy.OPERATIONS` 继续将操作映射到旧默认受众，供现有调用、`uci_catalog` 和 `collection.registration` 使用。准许登记的组合为这些旧配对，加上 `analyze`、`export`、`export_aggregate` 各自与 `local_authenticated` 的配对。`register_grant` 仍要求 `manage_grants` 和明示受众，表外组合拒绝登记。`applicable` 增加仅限关键字的 `audience`，旧调用省略时沿用旧映射，显式传入时只匹配该配对。表外组合、缺少适用 grant 均拒绝，历史 grant 保留原受众。

`require_use` 沿用旧的操作权限与默认受众。其 `analyze` 和 `read_current(..., 'analyze')` 仍要求 `review_observation` 及 operator 分析许可。新用户入口从真实 Session 取得活跃账号，由服务端按动作向 `ReadContext` / `applicable` 显式传入受众，管理员走同一入口也按普通用户判定。每个产品、对象/期、指标、数据日期段、字段集和受众独立匹配，当前 PG 时钟同时检查 grant 生效、到期和留存期限。一个 allow 须完整覆盖该用途所需字段。相交的适用 deny 或未解释的限制优先拒绝。日期精度无法表达的小时级用途先拒绝，直至有可实施的更细依据。

### 4.3 模型与所有权

- **SavedQuery** 放在 `accounts`。随机 ID、`owner` 外键、`synthetic_scope`、受限长度标题、确切 product 外键、版本化规范意图（固定起止/锚、指标、单位、窗口、标准、质量、方法、粒度、排序）、意图修订号和时间戳。按 `(owner, synthetic_scope, created_at, id)` 排页。最多 5 个目标，子表保存位置和 `City` 或 `SiteEpoch` 外键，限制 `(query, position)` 唯一、目标类型互斥、禁止重复实体。同事务校验产品/域/站点身份。用途失效、目录删除时私有意图可保留，目录外键 `SET_NULL` 后由类型和空引用表示原目标不可用，不按名称重连。允许保存与当前基线比较的服务端摘要时须有单独留存依据，否则仅保存意图，复访表明无可用旧基线。
- 创建绑定 `request.user` 并核目标。创建/修改与 `run` 均校验有界 JSON、方法版本和域，不接受任意 URL、SQL 或导出路径。列表和详情先按 `owner + scope` 限域，仅投影本人意图及有权的身份标签。修改/删除以相同域锁定对象，PATCH 重验变更的全部条件。无权读数据时仍允许本人删除。复访核活动会话、产品是否仍可用于研究、站址/来源身份、当前输入和方法。同条件、同方法下按 §5.4 的统计内容摘要决定 `data_changed`。仅可信水位推进时返回 `200/current` 及新的 `input_version`。缺可留存的旧基线时只提示无基线。方法已替换或站址已变时提示重新选择/确认。原历史期仍有效时可按原期读历史。区分禁用研究用途与暂停采集，后者按当前许可仍可回读合法历史。用户未明确修改时不平移固定日期。
- **ExportTicket** 同属 `accounts`。随机 ID、owner、域、导出类型、规范输入组、字段、受众及各产品的用途/范围/依据引用、方法/格式版本、服务器私有版本摘要、创建/过期/作废时间。约束 `expires_at > created_at`，查询走本人域索引，清理走到期索引。客户端不能指定 owner、输入摘要、有效期、文件路径。票据不存 CSV 字节、观测数值和第三方标签。准备/下载严格按 §5.4，列出和删除同样按本人限域。
- 迁移从 `accounts.0001_initial` 增量开始，按实际外键依赖 `observations.0010`。空表/可空增量，无默认真实产品授权、无历史观测回填。使用同一事务更新私有资源和目标引用。撤权处置按产品定位票据/可选基线并清理无权留存的摘要，不以私有外键阻挡原目录删除。

### 5.2 应有、实到、有效与共同样本

采用版本化的**研究覆盖依据**，内容包括产品/研究集、对象或期、可用指标、口径、源时区、节奏/标签、预期起讫或离散区间、依据引用和版本。S05 首选小型服务端 profile 解析器。H 绑定核验成功的 `uci501-edges-v1` 与选站两窗，F 绑定项目自编的有据历表，真实 C/S 只有具备经确认的独立节奏及监测范围才能返回已知 E。H 依据可在读入前定义应有槽，导入后与独立原件核验。不得从最后到达的行、抓取次数、授权日期或用户提供的分母推出应有发布。暂无依据的 C/S 仍可按权看存量样本，分母为 `null`。S05 先不建调度/名册管理系统。

1. 为每列在 `requested_window` 内解析独立已知的预期区间，再与实体/站址有效期、指标/标准适用段按源时区求交。保留 `expected_windows`（可不连续）、已知/未知部分及依据版本。时区换算保留实际 UTC 标签，测试地方日边界、闰日和适用的夏令时缺/重复小时。使用授权段保护信息，不把失权天数从分母中扣掉后对外宣称全窗覆盖。
2. **E** 为预期集合的独立槽数。**O** 为其中有可归属规范记录的独立槽数，显式 `NA`/缺测也实到。**V** 为 O 中单位、窗口、标准、现行修订和质量均合格的槽数。先从获准全质量基表计算 E/O，再应用方法的有效性策略。`quality=valid` 的页面投影不得提前滤掉缺测记录而减少 O。无规范记录的被拒原包不能计作一个已知研究槽。来源仅在有可披露独立证据时归因。已知计划外实到单列获准样本，不能填入另一槽。重复投递去重到键/时间，出现多个互斥口径不能任挑一行。
3. **E共** 为所有列各自预期槽**集合的交集**大小。**P** 为 E共 内所有被比较列在同一时标都有兼容有效值的槽数。三对象比较使用三者共同集合，不能串用两两交集。结果给单列 O/E、V/E 和共同 P/E共。无可信节奏、覆盖域未证实或含未知段时，该范围分母/比率置 `null`。获准的实到/有效数和实际配对样本可另行说明。已知且明确的时轴没有标签、或两列已知预期集合相交为空，可报 E 或 E共 为 0，比例 `null`。权限不足时遵守 §4.2 的拒绝规则。
4. 单列整期解释须 `E>0 && 4*V>=3*E`，多列整期解释须 `E共>0 && 4*P>=3*E共`，使用原整数判定，显示舍入不影响结果。只对证据完整的**预期子窗**达标时，结论限定子窗并标 `partial_coverage`。请求全窗仍为证据不足。未达标可给获准原序列、分桶有效数、诊断原因及配对样本。整期均值解释/排名字段为空。两列各 18/24、共同 12/24 时输出 75%、75%、50%，全天排名为空。
5. 默认可靠统计中 `valid` 且数值非空、未退役/未争议才计 V。真零计入，`missing/censored/invalid/suspect/disputed` 分别列获准原因。`<3` 保留方向及限值，不替成 0、3 或一半。待核峰值保留明细。有效极端值仍进统计。未决候选与旧版不取代当前可靠值。授权的原因不足时用 `unknown`，不披露管理 Run 或受限记录存在性。

### 5.3 方法、聚合与可复算性

在 PG 形成 `预期槽 → LEFT JOIN 获准当前行 → 逐列资格 → 共同样本 → 分桶聚合`。先归一每列每槽唯一性。对 E 未知的情形单走已授权实到关系。时间序列在可知槽上留缺口，不对历史空位插值或回填。分位数使用确定的线性插值（位置 `(n−1)q`），方法版本固定端点、舍入和输出精度。阈值、计算和 CSV 均使用未按显示精度舍入的数值。PG 的分组、窗口、排序分位数和 `corr` 可覆盖本阶段。用小样复核数值精度，必要时用 `numeric` 排位插值。应用层仅做有界结果投影，不新增 Pandas/NumPy 依赖。

| 结果 | 逐项定义与不足处理 |
|---|---|
| P0 趋势、分布、浓度统计 | 小时序列包含真实时标与空槽。按源地方日/月归桶，给每桶 E/O/V、有效数、均值、最小/最大及其时槽、中位数。极值并列给最早的获准时刻及并列数。频数分布用方法版本内同指标/单位的固定边界，注明闭开端点和溢出档。月均 `SUM(有效小时浓度)/COUNT(有效小时)`。少数样本的描述注明样本范围，整期解释依 §5.2。浓度小时均值只用同质小时窗，滚动窗保持原口径。 |

### 5.4 输入版本、同步导出与失效

实时计算统计和支撑明细。`input_version` 描述规范父查询、方法/质量/覆盖版本、获准身份及其期段、预期槽、排序后的当前键/修订/资格/争议及可信 scheme/水位。同一父查询的统计、明细和 CSV 共用此数据版本。另算操作专用的授权/投影签名，绑定受众、每个操作的有效依据和期限、实际字段与署名、格式版本及固定的排序。跨用途对账比较前者。签发/领取同一票据要验证两者。排除本次请求时钟、动态年龄及不改变输入的重复/迟到回执。摘要覆盖候选范围内影响 O、V、P 及实际输出的全体获准行，包括新填空槽、退出有效集或删除的键。导出签名还绑定输出所用的血缘/贡献批次获取时间。产品 `rights_version` 与 Change 可供内部快速判断是否需要重查。对用户可见的版本与变化提示只反映本次授权范围内的变化。隐藏对象发生修订或同产品无关 grant 变化不应成为探测信号。摘要采用带用途和作用域的 HMAC，持久化摘要也核留存依据。

**C03 · 复访比较统计内容。** SavedQuery 仅在有留存依据时保存统计内容的作用域 HMAC。按同一意图和方法，对获准的预期槽、各槽样本归属、未舍入规范值、单位、质量（含删失方向/限值）及有效/配对资格取摘要。可信来源水位、回执时间和导出授权签名只用于相应的版本或用途复核。这样可以识别总均值相同但时槽数值已变的订正，也可以在仅推进水位时继续展示相同的统计结论。

| 输入变化 | 统计、复访和旧票据的预期行为 |
|---|---|
| `v1=10 → v3=10 → v2=20` | v3 推进可信水位，沿用同一当前内容修订、资格和统计内容摘要。`input_version` 改变，v1 票据须重备，SavedQuery 复访仍为 `current`。v2 只留迟到记录，沿用 v3 的两个摘要。其他输入相同时 v3 票据可下载，统计与 CSV 均为 10。相同水位同值重投也沿用该版本。 |
| 可信异值订正、确认映射更改、未决争议 | 可信异值换当前修订，资格改动/退役/迁键可能改变 P。争议候选不进入 V，当前行受 disputed 遮盖，未解决的争议维持排除。版本变化令旧下钻/票据失效，从获准新输入重算。 |
| 许可、身份、方法和时间 | 重新判定各产品各操作。适用许可撤回/自然到期或新 deny 生效时立即拒领，即使 `rights_version` 或观测行没变。站址迁移、覆盖依据变化、新增落在原空槽的键、算法变更也触发范围内重验。特定用途撤销后重新获准，旧票据不得自动复活。 |

**C02 · 准备与下载各用一个 PG `READ COMMITTED` 事务。** 在最外层 `transaction.atomic()` 内先按 `owner + scope` 定位私有资源及候选依赖 ID。以 `SELECT … FOR UPDATE` 按序锁定涉及的 Source、Product、目标站址期所属 Station、所用私有行、User 及当前 Session，持锁至提交。取齐锁后重读归属、依赖、意图修订及票据状态，以同一个锁后 PG 时刻判定各产品的用途，再从该状态计算版本、行集和签名。多条 SQL 的一致性来自这些写端共用的锁。Product 锁覆盖窗内的首发和空槽填补，Station 锁覆盖跨产品共用站点的迁址。可变覆盖依据的写端也须取得对应的来源、产品或站点锁，固定 profile 按依据版本核对。若锁后发现依赖集改变，回滚并要求刷新，依 §4.1 优先处理失权或非本人。

共享行的取锁顺序为 `Source → Product → Job → WorkWindow → Station → SavedQuery → ExportTicket → User → Group（仅依赖组权限时）→ 数据库 Session`。各路径跳过无需的层，同类行按主键升序。多来源请求先锁全体 Source，再锁全体 Product。导出只读观测键/修订，既有写端在各自的产品锁内处理这些行。

| 并发入口 | 与准备、下载共用的锁及写入顺序 |
|---|---|
| 授权与处置 | `register_grant/revoke_grant` 和 `disposition.reconcile_product` 沿用 `locked_catalog_product`。CNEMC 先锁 Source 再锁同源兄弟 Product，其他来源锁目标 Product。`reconcile_catalog` 依次锁 Job、WorkWindow 和 Station。相交票据的作废、失权摘要清理在原事务中按上述私有行顺序完成。处理跨产品票据时按其冻结依赖判断相交，持票据锁时禁止回取另一产品锁。 |
| 观测与目录 | 站点批次 `revisions.ingest_batch` 先锁 Product，再按主键锁 Station 后写键。`correct_mapping` 在同一 Product 锁内先锁原键，再由 `locate` 锁目标站并处理目标键。`catalog.relocate` 直接锁 `Station → SiteEpoch` 并提交。下载与迁址在 Station 相遇，迁址端无需反取 Product。 |
| 私有资源 | SavedQuery 的 run、PATCH 和 DELETE 按本人锁同一行。换目标先定位新旧依赖的并集，再按序取锁和核意图修订号。已签票据使用自身冻结的条件，改删方案不改票据。取消、清理与下载按同一 ExportTicket 行串行。仅删本人资源可跳过数据用途判定。准备在 User 锁内计本人配额，只插入新票，旧票清理另行执行。 |
| 账号与会话 | 停用更新 User。`profile.change_password` 锁 User 提交新密码后另行 `logout`，两步之间旧 Session 的哈希已失效。`views.sign_out` 删除当前 Session 行。账号操作持这些锁时不回取产品或私有行。普通导出只使用活跃身份、本人归属和场景许可。对确实依赖 Django 权限的路径，直授权限/成员变更先锁相应 User，组权限变更锁 Group，读端在 User 后、Session 前按主键锁所用 Group，再查实际权限关系。 |

**准备请求**经真实 Session 和 CSRF 校验后，从锁后快照核对请求版本、各用途和字段。固定生成时刻、列序和编码器，对同一次有界 CSV 编码计数据行数、字节数和字节摘要，与该快照的 `input_version`、授权/投影签名一起冻结。最终复核通过才在该事务写票、提交并返回 201，随后释放内存。零行返回获准的 `200/no_data`。截止取创建后 15 分钟、使用/留存期限及适用未来许可边界中的最早者。按本人限制活跃票据数量及频率，超限提示清理或稍后重试。PG 只保存本人短期元数据，源相关依赖须有 `export_manifest` 留存权。

**下载请求**在锁内重算输入、授权和投影，沿用票据的生成时刻和 `csv.writer` 编码，核对冻结的版本、行数、字节数和字节摘要。两端都在内存编码后、提交前以新的 PG `clock_timestamp()` 复核 Cookie 所指数据库 Session 行的 owner、到期及与当前 User 对应的认证哈希，以重新加载的 User 重验账号和适用权限，并核对各输入全部用途的授权签名和期限。下载同时核票据截止。成功提交才将完整字节交给 HTTP 层。先提交的变更优先，已发送至客户端的字节超出平台撤回范围。

**等待上限。** 准备/下载在锁前设事务级 `SET LOCAL lock_timeout = '1s'`、`statement_timeout = '5s'`。整笔预算初值 10 秒，以应用单调时钟计时，每条 SQL 的语句上限取 5 秒与剩余预算的较小值，预算耗尽即回滚，分批编码及提交前检查截止。锁等待、语句或总预算超时、数据库报告死锁均回滚，在事务外返回 `503/database_unavailable` JSON。失败时不签票、不发 CSV 附件头或部分字节。下一次请求重新取锁并鉴权。V14 注入超时，V17 实测后冻结预算。

**CSV 采用 UTF-8 和固定表头**，列选择有白名单。每条数据行带来源/数据集及署名、生成时间（固定本票据时刻）、源时区、观测标签或汇总桶范围、指标/单位/窗口/标准、质量或样本覆盖、输入/方法版本和加工说明。汇总行带足以解释的分母。明细行可对回键/版和获权采集时刻。必需字段/署名缺权则拒绝。可选字段只能显式选择，禁止 ORM 任意字段投影。空值、删失限值、零用独立质量/限值字段区分。从服务端生成类型化数值，文本规范化后识别前导空白、BOM、控制字符及 `= + - @` 等表格公式前缀并强制文本转义。普通 CSV 引号只处理定界。固定附件名，无账号、原包或私人备注。拒绝响应不带 CSV 下载头。

**S05 负责自己生成的票据和摘要**。CSV 仅在内存中存在。适用 grant 变更时，在 `register_grant/revoke_grant` 原事务、同一产品锁内，对尚有效且输入范围/受众/字段/用途相交的票据作废（写 `invalidated_at` 或删除）。核对有限票据的冻结依赖，不能按全产品任一隐藏 grant 变化向其他用户报错。已登记但将来才生效的限制，把相交票据截止提前到该边界。即使中间没有下载、临时 deny 后来撤销或新 grant 重新放行，作废或已到截止的旧票据也不能复活。数据订正及其他变化仍在每次下载以当前输入复核。票据过期即失去领取能力，定期/启动时有界删除已过期元数据。源撤权、留存到期或覆盖目录处置时，接入现有 `disposition`，按输入产品清掉失权票据及 SavedQuery 中须处置的摘要，保留仍获准的用户意图和不受影响产品。撤回后即使在两次下载间重新登记也以新依据重新准备。停机硬截止按已有 `policy.applicable` 留存约束执行，无法满足留存/清理条件就拒绝持久化。S06 承接其他受控副本、备份/恢复、跨模块传播和演练。

**V14 的竞争断言**

1. 在准备选数和编码之间放行订正或填槽写端。准备先取齐锁时，201 票据的输入版本、授权签名、行数、字节数和摘要均与写前同一组 F 输入独立对账。写端先提交时，使用新版本可签写后快照，携旧版本得到 409，已失权得到 403。失败请求产生的新票据数为 0。
2. 下载先取齐锁且使用条件持续有效时，提交后取得 200，整份 CSV 能按冻结签名对账。写端先提交时，会话失效或本人票据仍在但已失权返回 403，获准输入因订正或迁址改变返回 409，换用户或票据已取消删除/处置删除返回 404。同人两 Session 中，退出只拒绝已退出者，改密拒绝两个旧会话。只撤 `review_observation` 时，仍有普通用户导出许可的请求返回 200。并发 PATCH/DELETE 与 run 只允许读取一版完整意图、报告 409 版本冲突或返回 404，既有票据仍按自身冻结条件判定。正常交错和反序多产品请求须在预算内完成，无死锁。
3. 让票据 TTL、grant 有效期或未来 deny 的生效点落在编码期间，最终复核按失权 403、仅票据过期 410 分流。无人领取期间相交 deny 的登记再撤销、撤权后再授及处置任务停顿，均不能使失效旧票可领。分别注入超限锁等待、慢 SQL 和慢编码，要求在 §5.4 预算内回滚并返回 503。所有拒绝仅返回 JSON，无 CSV 字节或附件头。

## 8. 工程质量、操作与证据交接

- **迁移与回归**。放行后先核待测 checkout/容器源码指纹、连接角色、自有库标识和 `CNEMC_MODE=off`。隔离运行器按 `scripts/verify_s04.py` 的模式创建无外联网络、随机命名的 tmpfs PG，仅在核实所有权后迁移/导入/清理。在该库执行 Django `check`、`makemigrations --check --dry-run`、`migrate --check`、pytest、Ruff 和项目配置的 mypy。验证空库和 S04 旧库升级，回退方案优先关闭新增入口并保留用户意图。仅在可销毁库验证反向迁移的数据损失范围。验证器拒绝指向共享库、既有卷或其他验证任务。
- **复算示例**。V04 的安全 F 契约样例使用 2024-01-01 一个源地方日、同城两个不同 `site_epochs`、`PM2.5`、`µg/m³`、`hourly_label_unspecified`、`not_applicable`、`scope=synthetic`。`compare` 返回 `E=[24,24], V=[18,18], E_common=24, P=12, ranking=null`。客户端原样携带 `selection + method_version + input_version`，在 `details` 选择 `support=paired`，应得到 12 个时刻各 2 条支撑行。准备汇总/明细 CSV 时显式选择 kind 和字段，再从同一用户 Session 下载。操作文档给出实跑后的请求/响应、`use_denied`、`input_changed` 和 `expired` 例子。私有 ID 和值只用自制 F。
