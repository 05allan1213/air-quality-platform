# CNEMC 数据源接入 Implementation Plan

**2026-11-22 · S04 前补充任务 · 基础实现完成；单次实源验收按操作者声明恢复。** 目标是让已有 S03 Worker 在登记范围内读取 CNEMC，由同一 PG 账本解释每一次请求、观测、缺口和拒绝。基础能力可在隔离 F 环境验收。个人开发环境的一次限定技术测试记录操作者的真实声明及精确请求/留存范围，不额外要求许可文件路径、官方条款编号或书面版本证明；正式扩量、周期运行、公开或再分发仍按实际适用的外部限制分别处理。T11 仍有独立放行条件。S04 可复用获准留存的真实 C 观测，也可并行开展其他合法本地数据工作。

本计划基于 `main@b8c30ae7bac22db03bc2d11ed27e4862b390571a`。工程证据、逐端点字段和样本定位分别见 [核查报告](../verification/CNEMC_PRE_S04_AUDIT.md) 和 [12 接口映射矩阵](../design/CNEMC_ENDPOINT_MAPPING.md)。

## 2. 产品选择与调用量

周期均为**候选配置**，实际上限取适用授权、源级限额及本地执行预算的交集。`K` 为明确登记的 C 城市数，`M` 为 A04 的授权城市数。城市名单初始为空。所有周期 Job 初始禁用，单次现场验证使用无 `next_due_at` 的获准人工 Job。

| 场景 | 启用方式与请求预算 |
|---|---|
| 初始化 | 登记 Source、按产品分开的 `Product.code`、上海时区、工作身份和条款版本。导入经核的源城码、官方全称、站码、站址有效期与名册依据。已有目录时外部初始化请求为 0。确需在线字典时 A11 一次，A12 每个获准且需要的省份一次，按目录变更复核，不随进程重启循环访问。 |
| 全国小时 + 重点城市详情 | A01 全国 L 一次，A07 全国独立站点产品一次，A03 各白名单城市一次，合计 **`2 + K` 次/小时**。A07 单包本次实测约 1.25 MB。全国包获准、地方处理权较窄时在本地按权筛选。只有地方获取权时禁用 A07/A10，选 A04。 |
| 按城站点模式 | 对 `M` 城取 A04 需 **`M` 次/小时**，全国 A07 需 **1 次/小时**。例如 3 城为 3 对 1；假设逐一访问 338 城会发 338 次，A04 对所有城市的可用性未逐项验证，A07 的 341 个 `Area` 也不是 338 城名册。在相同业务范围内选择一种常规站点路径。仅用 A04、A01 和 K 城 A03 时总量为 `M + 1 + K`。 |
| 发布时间与增量 | 研究记录的整点后二十分钟左右是发布说明。本地候选首读为北京时间 H:25–H:30，按实测和预算错峰。`due_at` 是实际执行时刻，`target` 是期望的源整点，两者分开。窗口只认可目标时标。旧包记 `no_new/outside_target`，额度允许可配置最多一次延后复查或等下一周期，延后复查也计费。新鲜度按每个指标的实见时次评估。 |
| T 与 S 的近期缺口 | T 有明确展示/研究需求才对 `K_T` 个城市刷新，每轮最多 `K_T` 次 A05，一城一包取符合目标的近期 AQI。A07 在途失败或整点缺报时，获准的 A10 每个合格缺口整点一次，共 `H` 个整点最多 `H` 次初始读取。A08 仅按获准的指定站尝试单站近期产品。若额外追 A09，按登记站数另计。只有具名研究需求才读逐站的 A08/A09。用户打开页面只读已存数据。 |
| 日产品 | A02 候选每天一次取全国最近发布日。A06 仅用于 `K_D` 个登记城市，每城最多一次常规读取/日或一次有界缺口读取。按 `TimePoint` 提取报告日，按日期去重、排序，已有当前日值继续走修订核查。日模式、T、补采、初始化、复核与失败重试分别纳入总量预算。 |

例，`K=3` 的全国组合为 5 次/小时，`K=338` 为 340 次/小时的容量推算。无 QPS 服务承诺。初次验证选单并发、有限地域与总次数，预先列出每一类请求及最坏重试耗费。预算不足就减少城市或暂缓某个产品。频率配置需同时校验 `min_interval_seconds/max_concurrent/period_seconds/max_requests`。一个业务源同周期内的 A01、A03、A04/A07、T/D、字典、复核和重试共享来源配额。

## 3. 写入、窗口与恢复设计

1. **来源及请求契约。** 用固定映射从 `Source.namespace + Product.code + contract_version + Run 的端点` 选方法、常量源、路径、参数位置、返回形状、指标集、范围和硬上限。原 F 注册表与 `X-S03-Target` 留在 F 分支。真实源仅允许固定 HTTPS origin、合法参数与 TLS，HTTPX 只发一次请求，有明确总期限，禁止跟随跳转。A03 用 `cityCode`，A05 用 `citycode`，A04 用全称 `cityName`，A10 的 `date` 用表单编码。预计 A07/A10 可先以 **2 MiB、2,048 行、2,048 个独立名册代码**作 F 验证的候选上限。保留每字段、嵌套、重复键、解码和行数限额；超量整包拒绝。先沿用 identity 编码。如果授权现场只提供压缩响应，单独验证压缩输入与解压输出两道限额再放行。
2. **每次出网先匹配整个包。** 全国包检全国与全部返回字段，按城包检整个城市，指定站检该站完整响应，趋势还检可能返回的整段日期。A10 按其唯一整点授权，任何一行错时按契约异常整包拒收。对无日期约束的 latest/滚动上游，只有整包覆盖许可或提供方确认的硬边界才能缩小获取日期范围。当前 `f-latest-v1` 使用 `date.min..date.max` 的保守检查；单轮观测到 24 小时/14 天不是硬边界。之后按本地选择分别查 `process_local`、`retain_normalized`（含 `collection_ledger`）。源字段、诊断摘要/哈希、原包、复核、展示、分析、截图、导出、再分发、备份/恢复逐项授权。采集包仅在有界内存处理，常规链不写原包或响应哈希。无权的字段值不写日志、测试回执或 Redis。
3. **目录与分母。** 首次可用获准离线目录登记 `CityIdentifier/StationIdentifier/SiteEpoch`，明确证据、生效日与来源。A07 的非零城码与该时次目录交叉校验。A04 城码 0、A10 缺城码时须有覆盖该标签/统计窗口的站码和站址期。研究回执可发现候选目录问题，目录调整经 `catalog` 的锁和受控操作处理。实包的返回条数不决定应到 E。冻结的名册有未解析对象时，选择暂停等待目录修复，或明确标为未知 E，不允许静默缩水。按站点实际监测方案计算应到指标，若仅有站点名单而缺指标依据，把已知对象覆盖和未知指标分母分开。对真实目录、配置中 `expected_codes`、可选源文本的撤权/到期做实测；同源跨产品共享目录时先查其他合法依据与历史引用。
4. **A07/A10 与原窗口。** A04 按城与 A07 全国使用不同产品码、独立业务窗口。A07/A10 的同产品认定至少核对发布说明、站码/站址期、同整点七项、单位/窗口和缺测含义，覆盖多个整点、城市与部分缺值，并核两条路径的获取权和后续用途一致性。未满足时保留全国 S 缺口，A10 可作获准的独立研究对照。满足时 A07 正常尝试与 A10 精确补采共用全国 S 同一 `product/scope/target_start/target_end/profile`。`profile` 表示稳定的业务窗口契约，实际端点放在 Run，一次 HTTP 一份预留。重试继承原路径、原意图和次数；最新窗已过期的后续恢复另记有界的 `backfill` 尝试，链接原 Run，复用原 Window 和已认可子项。`locked/authorized/reserve` 逐次核产品、路径及获取/写入权。权限或内容口径不同的两路不得共享一个授权投影。
5. **有限追赶。** `latest_observed_at` 取有权保留的实际观测，不用 `last fetch` 推定之前齐全。取冻结名册、PG Window/RunItem/Receipt、现行资格与运营日期的差集识别缺口。断源期间连 Window 都没建的整点也要从批准的时间表找出。A10 以最近可靠的全国源时次为锚，初始候选回看最多 23 h；锚过旧、在未来或证据不足时先在授权内取得当前时次，或停在待核。挑最早仍可取且有合格缺口的时次。每次扫描使用配置的 lookback、页数/窗口数和补采请求预算；停机久的 latest 槽批量标为不支持或记录有界缺口区间，并把游标推进到当前周期。A01/A03/A04 没有指定小时能力，禁止发 latest 请求回填旧窗。A05 一次覆盖一个有目标的滚动 T 窗。相邻两窗的重叠小时按同一 T 观测键去重。后一窗包含前窗漏报的小时，就用后一 Run 的 Receipt 建立该小时观测，精确读可见。前窗保留原有 E/O 和回执，后一窗按自己的 RunItem 对账。若后来收到异值引发争议，两窗中已收到的格都按现行资格重新核算 V。只有同业务窗的尝试才能更新该窗的认可格。
6. **缺口资格、结果与修订。** 只安排尚未收到、或前次技术失败而可补的格。有记录的 `NA`、未监测、争议与不可解释指标进入相应质量路径，不无限重取。A10 确认 `[]` 可保留 `no_new` 和有界的不可补/当次无数据原因，禁止扫描器为同端点同窗反复重开；429/403/TLS/结构漂移按原源/产品暂停，恢复需核条款，429 尊重 `Retry-After`。调度延后复查、补采、重试共享源预算和每窗尝试上限。候选原时标/端点证据挂在有权的 Run/Receipt，同规范语义采用统一溯源依据，避免 ISO 与毫秒文本差异制造内容争议。正式候选 `token=None`。同键同值仅增回执，无序异值写候选、质量事件与资格变更。未知标准保留获准官方描述，平台推断颜色和需已知标准的排行关闭。

### 三项需落实到 PG 的控制

- **限定验证的总次数。** 在 `UseGrant` 上登记实源验证范围和不可循环的 `max_total_requests`，覆盖端点、对象和实际有效期。每次 `reserve` 在现有 Source 锁内检查累计预留，并将 Run 与本次消耗的验证授权关联，随后同事务转为 `possible`。同一授权下的多个 Job、手工 UUID、重试和重启共用总额。跨产品的验证若只有一个总次数，可在登记时分配给各产品。分配之和受总额约束，分配不清的产品先保持关闭。滚动配额释放后，已用掉的绝对次数仍然计入。适用的多个上限取交集。总额用尽时给出终态原因，限定模式要求匹配该轮验证授权。新增 Job 或普通宽泛许可都不能替这一轮补充次数。变更总额需要新的授权记录和审核依据。
- **处理范围与覆盖分母。** 将“本 Job 获准处理的对象×指标”与“该窗独立名册证实的应到格”分别冻结。前者默认空，可选有限白名单，只有完整整包处理权才允许全部。按实际实体、时次和指标取配置与 `process_local` 的交集，经 `retain_normalized` 校验后才生成可持久项。在读取身份和时间并作结构校验后，先裁剪对象和字段，再调用 `_measurement/normalize`。计数、包级诊断、RunItem 与 Receipt 只投影获准范围。后者用于 E，未知时 `E=null`。`selected_use`、`writer.manifest`、`read_window` 与处置依据同一处理选择。创建 CNEMC 窗口时把规范化后的处理选择（范围模式、排序去重的对象与指标）冻结为 `WorkWindow` 的受权字段。每次 `register` 复用该窗口，均在 Window 锁内比较处理选择、expected 和名册依据，再建 Run 或预留 HTTP。等价 Job 共窗，选择不等返回 `window_contract_conflict`。`claim/reserve/commit_chunk` 重核同一契约。`read_window` 针对窗口冻结的选择逐格检查现行 review 与 retain 权限，部分读权只返回获准子集的格与计数。处置时清掉窗口中失权的选择。
- **已运行 Job 的名册失权。** `s03_freeze_job` 保护历史配置。为新增 CNEMC Job 增加不可逆的处置状态，在原触发器内只放行“禁用 → 已处置，同时清空名册、依据文本和源派生处理选择”的单向转换。其他冻结字段继续受保护，已处置配置拒绝恢复或编辑。沿用 `DispositionJob` 和产品处置服务。涉及同源目录时，统一按 Source → Product（按主键排序）→ Job → Window 的顺序加锁，再与当前站点锁顺序衔接。避免在已持 Product 锁后反向取 Source 锁。处置时先按可留范围处理观测、回执和所有相关窗口，再脱敏旧 Job，所需的最小审计须有留存依据。部分撤权时保留仍合法的格与查询血缘，旧 Job 同样停用，按剩余授权登记新 Job。对 `CityIdentifier/StationIdentifier/SiteEpoch` 逐条核其他产品是否仍有目录依据，有依据者保留，失去全部依据时按 FK 依赖处置关联观测和目录，必要时用有独立保存依据的匿名内部键维持引用。源派生名称、代码、坐标与证据文本也在处置范围内。无依据保留的内容须能删除，否则该目录配置拒绝准入。仅保留有权的 PG 预留事实供额度对账。冷启先处理到期处置再开放该源。若配额关联本身失权，停用对应验证授权，禁止清除记录后重新计次。
