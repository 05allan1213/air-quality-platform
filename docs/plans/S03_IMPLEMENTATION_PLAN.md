## 3. 分产品请求和候选契约

服务端注册表把 `(source, product, contract_version, environment)` 绑定到一种适配。F 只绑定内部模拟 origin，实源 profile 只接受对应发布者和同族产品。Job 只能选择注册 ID、已核目录范围、周期和允许的目标窗。下表的路径来自 V3.0 §6.1，字段拼写参考总体实施方案 §2 指名的本地 `CNEMC_FIELD_MAPPING.md` 和 `crawler.py`。这些是拟支持的线格式，实源兼容性留在获准核验。F 自制对象码、时间和值。测试 HTTP origin 固定为隔离服务，历史观测的实源 origin 候选为 `https://air.cnemc.cn:18007`，启用需单独登记协议、主机、端口、路径和权利。管理请求、响应内容和文件都不能指定 URL 或凭据。

**候选与质量。** 读取前先核完整请求授权，核完响应上限、顶层及身份字段后，将每个受支持的测量映射为 `object_code, indicator, source_time, raw_value, raw_unit` 与准许保存的来源说明。`ProductProfile` 指定 shape、来源时区、窗口、标准及证据，`BatchContext` 使用实际读完时间。按字段调用 `normalize()`，随后构造 `Candidate`。本地 ISO 在有依据时按 `Asia/Shanghai` 解释，`.NET /Date(…)/` 用整数 UTC 毫秒还原，转换为与来源时区一致的偏移再交现有时标校验。有权时保留原时标与解释依据，双时标不一致、模糊时间、溢出、非整点和未知单位产生固定错误码。未知小时端点使用 `hourly_label_unspecified`，不得把采集目标时窗写成测量区间。

零是数值，空串、`NA`、`/`、显式 JSON `null`、缺键、`<3`、非法值各有原因。保留 JSON 十进制精度，布尔/非有限数及超精度拒绝。为 `null` 增加受控显式缺测映射，避免与空串或字段缺失合并。可疑峰值入待核。AQI 标准由发布或可核文件给出，未知时保存获准的来源描述，站内等级、颜色与版本相关可比性保持空或否。等级文字和首污属于来源字段，仅按登记字段集投影到 AQI 修订的限定元数据，不能塞入错误文本或宽泛 JSON。对同键同包重复按规范值分类，异值都交同一修订服务作无序争议，解析顺序不能决定当前可信值。

**版本与重放。** `revisions.locate()` 当前只接受合成产品的可信整数 `sequence`。采集适配器默认输出 `Candidate(data, token=None, scheme="")`，包括模拟线上行为的 F 适配器。独立取得的同键同值走 `duplicate`，无序异值走 `unordered_conflict`，争议期间可靠读取排除该键。S02 专用可信序列夹具继续验证同值新版推进水位、迟到不回滚及同版异值。将来若实源提供可核的顺序，须先登记产品级 scheme、可信依据、排序域及版本反例，再评审开放该分支。HTTP Date、发布时间本身、抓取时刻、ETag、包指纹和租约代次均不提供这个顺序。

**有界 HTTP。** F 验收初值为连接 2 s、读/写 5 s、连接池等待 1 s，覆盖整个请求和流读取的硬截止 15 s。L 最多 512 行/1 MiB，C 1 个对象/64 KiB，S 256 行/512 KiB，T 最多 24 个不同小时并限 48 行/128 KiB（容纳有限重复）。先限传输字节，再限解码字节、嵌套、行、字段长度和候选数，缺 `Content-Length` 也逐块计数。初版请求 `identity` 编码，可拒绝未支持的压缩和不符的内容类型。截断、越限或顶层错误停止解析并按 §5 分类。TLS 校验开启，关闭自动重定向、环境代理、传输层隐式重试和正文调试输出。测试允许的内网服务与将来实源白名单分开注册，固定方法/路径、参数编码、解析目标地址和网络出口。实源限额取经确认的条款与本地上限中的较严者，未知为零请求。上述数值仅为离线工程预算。

| `Job` | FK Product、固定请求 profile/稳定范围、节奏/时区、登记的执行账号、下一到期时刻、暂停原因和版本。范围/契约变更新建配置版本，已开窗使用原快照。 | 草稿/关闭 → 启用 → 暂停 → 受控恢复/停用。默认关闭。每次触发追到配置版本与主体。 |
| `WorkWindow` | 唯一 `(product_id, scope_key, target_start_utc, target_end_utc, retrieval_mode)`，全部非空，CHECK `end > start`。Product 已唯一归属 Source。保存目标类型、独立预期清单依据或“未知”、当前 fetch 所有者、单调代次、租约和一个窗口结果。`scope_key` 来自服务端规范化目录。 | `open/active/waiting/closed/paused` 是生命周期，`new/no_new/changed/quality_only/partial/failed/paused` 是结果。手动补原窗更新同一行。窗口终结要有可查的范围、结果和缺口。 |
| `Run` | UUID、FK Job/WorkWindow、触发类型、触发者/执行主体、请求幂等号、前次 Run、原因、执行起讫、投递状态与下一动作时间、数据读取完成时刻、可空 Batch FK `SET_NULL`。一 Run 对应一次逻辑触发，至多实际发起一次 HTTP。 | `pending→running→finished/failed/paused/expired`，竞争者可 `coalesced`。投递独立记 `pending/sent/unconfirmed` 和最近发送时刻。Beat 槽按 Job/到期时刻唯一，手动请求按主体及客户端 UUID 去重（同号不同参数拒绝），补偿按前驱与重试轮唯一。不同触发可留下多条 Run。 |
| `RunItem` | FK Run/WorkWindow，稳定 `item_key`、代次、所有者令牌、租约、尝试状态、原因和 `accepted`。单位为同产品、来源范围内的一个对象/站址期 × 目标来源时标 × 规范指标/报告窗口/标准系列。已知目标先按登记目录和目标标签解析实体，写前按真实源时标复核。未知身份只留获准的未归属问题，解析成功后才分配稳定键。 | `pending/claimed→accepted/reread/retryable/rejected/expired`。`reread` 记录一次独立复读的裁决，`accepted=false`。唯一 `(run_id,item_key)`，窗口内条件唯一 `(window_id,item_key) WHERE accepted`。`accepted` 表示该格的处理回执获本窗认可，可含显式缺测或争议，V 另算。CHECK 认领所需字段、截止时间、终态及认可状态一致。两处 window 引用由复合 FK `(run_id,window_id)` 对应 Run 唯一组合，避免串窗。 |
| S02 `Batch/Receipt/QualityIssue/Change` | 同一次实际获取在获准保存血缘时建一个 Batch，Run 锁内首次关联。在线 Batch 可用 `identity=NULL`，用 Run 的内部 ID 追踪，不能用 nullable identity 去重。一个 Batch 跨多个分块。给 Receipt 增可空的 `collection_item` FK `SET_NULL`，允许一个子项对应多个候选裁决，保留单侧修订和原唯一约束。无键 `QualityIssue` 可关联本次 Run，行级问题可经 Batch/Receipt 定位到子项。 | 单个获取或错误可对应零观测。既有 `FixtureRun`、`ImportAttempt`、`DispositionJob` 各管原业务。退权删除 Batch/Receipt 后，获准的最小运行标记仍可独立对账。 |

**窗口选择。** L 使用登记的全国列表范围，C/S/T 按请求所属城市的稳定 ID 开窗，多城 Job 展开为这些规范请求范围。S 请求内仍逐站分项。L/C/S 的目标是一个源小时标签，T 是一次冻结终点的近期标签范围。对整点 `h`，可用 `[h,h+1h)` 选中标签 `h`，最近 24 个候选标签范围为 `[h−23h,h+1h)`。这个选择与测量本身左标/右标独立。两端以来源时区解释后转 UTC。范围、起讫和回溯方式描述目标选择语义，不含 Job ID、触发方式、取得时刻、Worker 或重试次数。相同槽的手动/定时/可补重试都解析到原窗口。若协议表示另一种产品选择，单独开窗并标明关联，覆盖只按各自选择核算。显式历史窗使用原范围和原标签，恢复时不得重算成当前小时。

**稳定清单。** 建窗冻结当时有据的对象覆盖期、指标契约及发布节奏，存登记版本和必要的获权对象/时槽范围。去重用稳定身份字段或服务端注册 ID，不以名称、行号、整包哈希、排列顺序或 Job 配置文本作为业务键。多 Job 同窗须兼容冻结契约，否则留受控配置冲突，不用新 Job ID 绕开。真实应到对象未知时，保留可识别的实到及其来源范围。一次响应的可处理清单与独立预期清单分别登记。冻结的指标/标准契约若与实到不同，记录错配及其资格，不通过更换 item_key 把额外格计入 E。实践中先限定单窗范围及行数，由一名当前执行者处理该窗，可并行处理不同窗。

### 4.2 排期、认领、提交与恢复

1. **登记。** 手动 Session+CSRF、单 Beat 唤醒的到期扫描和受控重触发共用计划服务。短事务检查准入，按规范键建立或复用窗口，创建/复用 Run，登记 `pending` 和到期时间。唯一冲突在 savepoint 外重新读取既有行。`Job.next_due_at` 与该批有限个到期槽的登记同事务推进。漏过多个小时则分页追赶，给不支持回溯的到期窗记录未获取缺口，归档后游标才前进。
2. **投递。** PG durable 事务提交后才向 `s03.collection` 发只含 Run UUID 的 JSON 消息。返回 202 附 Run/窗口 ID。发布未确认返回带同一 Run UUID 的受控 503。投递前重查主体/Job/许可。发布调用在事务外，更新 dispatch 使用条件更新/发送轮次，避免慢发送者覆盖已开始或终结的状态。提交后发布前崩溃、Redis 收到但发布方未确认、已标 `sent` 却一直无人认领，均可用同一 Run 重投。消息内容不承载许可快照或候选数据。
3. **认领与访问。** Worker 针对已提交 Run 锁窗口，核当前状态。已终态或同 Run 已活跃的重复消费直接返回。另一个有效触发在窗口持有活租约时记合流。已收口且无可补项的窗口同样只登记合流，返回原结果。可认领时用 PG `clock_timestamp()` 分配新的代次和每次执行独有的随机 owner，写窗口和 Run。知道的待办子项一起认领，动态项在响应列举后同代认领。真正打开 HTTP 前再按 §5 判权并预留请求预算，提交后在锁外访问。租约初值可取 60 s，每次实际推进先按旧 owner/代次和未过期条件续租，续期不能复活旧所有者。保留总运行时限。
4. **分块。** 在有界内存完成顶层结构、目标时间、身份及键冲突检查，圈定本次获准处理的稳定子项，并在短事务内登记本包的有限子项数和“已遍历本次响应”标记。包括该清单在内，任何执行者对 Run/Item、质量事件、错误和窗口的写入都需现行许可与同一代次守卫。假如后续崩溃，可从 PG 区分未解析完和未提交完。按稳定键排序，每块建议至多 128 个候选（同键争议组保持原子且有上限）。L 一次获取可超过 1,152 项，所有块复用该 Run 的 Batch，使用批次内唯一的内部候选序号。原始行定位仅在获权时额外记录。每块建立自己的 `transaction.atomic()`，前一块的已提交结果可供恢复。
5. **有效提交。** 重锁并验证 Run/子项属于同产品、同一窗/范围/时标，owner、代次、租约、Job 状态和现行许可全部有效。站点按 PK 排序预锁，调用共用 `apply_observation()`。以 `(batch,ordinal,rule_version)` 精确关联刚写的 Receipt 与子项，检查恰好一行。质量事件、版本、`RunItem.accepted` 和 WorkWindow 的聚合结果同事务写入，最后一块在同一事务收口 Run。提交前用新 PG 时钟重查逐项全部用途、操作者及许可时限，并作带 `owner/generation/lease_until` 的最终条件更新，必须恰好命中。未命中则抛错回滚**整块**，包括 Batch 的首次关联、观测、修订、质量及计数。在锁内最终条件更新处确定该块提交顺序，后继认领需等事务释放锁。
6. **失败与迟到。** 行级可解释异常归对应子项。事务错误先完整回滚，再以短事务按仍有效的 owner/代次登记失败或重试，旧执行者写失败也要被拦截。此前成功块不回滚。过期回收在窗口锁内结束旧租约及未提交的旧尝试，安排唯一后继 Run。老 Worker 即使先领后醒也不能续约、提交观测、关闭窗口或暂停新 owner。重复处理同一 Run/子项或重放已提交块跳过业务写。后继只为未完成且仍可取的子项发请求。已认可单元随同包再次出现时不重复认可。对**独立新获取**中获准处理的同键新证据仍用 S02 裁决并分记本次读取，可留非认可的复读明细。同窗因其他缺项合法重取时，已认可格的新读以 `reread` 关联自己的 Receipt，旧认可标记保留，当前资格随 S02 争议更新。跨 T 窗重见同一小时，各窗核各自实到，全库仍只有一个逻辑键。
7. **补偿。** 以 PG 扫描 `pending/unconfirmed`、超时未消费的 `sent`、已到 `next_retry_at`、过期租约和未收口窗。前两类重投原 Run，新的实际 HTTP 尝试建有前驱的新 Run。本包清单已封存、核对实际子项均已提交且 ACK 消失时，核 PG 后直接结束。只有空的明细表而无清单结束标记，应继续恢复。拟用 `collection.reconcile_due` 唤醒 PG 扫描，`collection.execute_run` 消费 Run UUID。Broker 重发独立于 HTTP 次数，按发送轮次设退避与上限，耗尽后标待人工对账并允许恢复同一 Run。扫描分页、有索引、可重入，先取候选 ID，再按统一锁序锁定并重查。事务内登记第一次启用或第一份待办所需的 DatabaseScheduler 唤醒。无默认业务排期。Worker 启动及受控命令 `s03_reconcile_due` 也扫描，Broker 恢复后单 Beat 继续唤醒。对没有进程运行的时段保留缺口。

统一锁序为 **Source（涉及来源配额/暂停时）→ Product → Job → WorkWindow → Run → RunItem（稳定键序）→ Station（PK 序）→ 对应观测/修订**。多来源/产品按 PK 升序，常用路径每次只处理一个。处置/撤权沿用产品锁，不在已持下游锁时逆取 Source。认领/投递/访问前、写入、处置分别是短事务，HTTP、broker 等待和退避均在锁外。关键索引覆盖 Job 到期、Run 的投递/下次动作、窗口租约、子项认可唯一键及 Batch 血缘，结合 PG 直接插入反例和双连接实测验证。

## 5. 授权、网络与可恢复的失败

| 生效点 | 判定与可验证行为 |
|---|---|
| 登记/启用和手动触发 | 采集新增 `manage_collection`、`run_collection`（Django 具名权限）。前者管理 Job/恢复策略，后者执行限域任务。定时使用登记、可停用的执行账号，记录触发来源。手动记录发起者，本次有效执行主体和适用权限均须有效。重试继承原来主体/权限边界。`is_staff`、S01 `run_fixture`、H `import_history`、超级用户身份均不能授予来源用途。缺准入的 Job 维持关闭，拒绝请求只留允许的最小原因。 |
| 计划/投递/每次实际访问 | 核 Job 和来源开关、适用 profile、执行主体、产品/受众/地域/数据日期/对象/指标/字段，独立确认 `acquire_online`、拟用 `process_local`、`retain_normalized`。授权必须覆盖**请求实际可能返回**的范围，含 L 全国、S 城内全部站、T 跨源地方日的近期序列和随包字段。最新端点不能界定最早可能日期时，要求适用的宽范围获取权或已核的服务端筛选。允许只处理/保存其中明确获准的子集，获取本身须已合法。 |
| 配额及限制 | 拟在 `UseGrant` 加可空、严格校验的采集 limits，绑定 `acquire_online` 的条款版本（适用来源/产品、最小间隔、并发、滚动时段长度及最多次数含重试、有效范围）。在现有 `Source` 增可空的共享暂停原因/恢复下限，记录适用来源级共同上限。无关用途继续使用原字段。保留现有 `applicable()` 的 deny 优先和未识别 `restrictions` 拒绝语义。完整依据不可拼接。来源级共同限制与产品限制同时成立，条款不明或未结构化时关闭。以短事务锁 Source/Product，在 Run 记一次请求预留、时刻和最长占用，聚合活动预留及时间段内已用次数，所有 Job/Worker/触发合并核算。崩溃、发送未明和临时失败照计预算，结束或超过覆盖 HTTP 硬截止的保守占用期限后才释放并发位。F 初值同来源并发 1、最小间隔 1 s、最多 12 次/分钟，专门用更小额度测边界。 |
| 处理与入库 | 拟由 `require_use` 为 `acquire_online` 绑定 `run_collection`，采集入口用同一 `applicable` 复核 `process_local`，将 H 专用的主体检查留在历史入口。请求许可的生效点为发起前最后一次 PG 检查及预留。外部发送与 PG 不能原子提交，已发出的请求可能在撤权后返回。收到响应先重查 Job、主体、原 `acquire_online` 和 `process_local` 的完整范围。若该次获取已撤权则丢弃正文。块提交在产品锁内再核此次获取仍获准，并逐实际行/字段检查处理与保存用途，写入与提交前判权在同一 Product 锁内，用新的 PG 时钟复核自然到期。账号/组变更以各关口重新读取的活动主体和具名权限为准，来源许可的撤回与观测提交经同一产品锁排序。明确要求在途即时撤销且无法履约的来源维持关闭。S02 `finish()` 拆出共享的时限检查和**服务端固定**的入口权限，保留历史入口契约，不接受调用者传任意权限名。 |
| 审计与物理处置 | `retain_normalized` 的必要字段和可选原字段依旧分开，整包 `retain_raw` 单独判断。首版 HTTP 只在内存处理，无原包缓存/重放文件。原时标、文字、首污、行定位、快照清单、计数、来源发布时间和批次身份按实际字段许可保留。摘要、ETag、包哈希亦需独立依据。Celery 参数、日志、错误、截图、镜像和测试资产只携内部 ID/固定原因等获准字段。可选来源描述仅作获权投影，因字段许可变化而脱敏时不生成“源方订正”。`reconcile_data()` 在现有处置事务内清理新增受限证据，重算仍有依据的部分。仅失展示权立即变更投影，失留存权实际删除/清理。已处置范围显示“受限/已处置”。操作审计可留允许的内部 ID、时间、原因。去重标识若可还原对象/时槽，同样清理。仅在另有依据时留不含来源内容的内部认领标记，否则关闭受影响窗口的自动重放并保留允许的最小关闭原因，避免处置后按“新缺项”再取。 |
| 可查询性 | 复用 Session/CSRF、限流和有界 JSON，管理高影响操作只通过服务。运行读端先核具名角色，再按当前范围核 `review`、留存及所投影字段。对无权范围隐藏计数、差集和对象存在性。只提供按窗、Run、产品/对象/指标定位与有界分页，不把后台状态暴露给普通读数请求。 |

**错误与动作。** 使用一个 PG `next_retry_at` 和重试预算控制实际访问。不叠加 HTTPX 自动重试、Celery autoretry 和 Broker 重投次数。以下是 F 初始策略，实源以更严的服务条款为准。

| 场景 | 运行、重试及暂停规则 |
|---|---|
| 连接超时、读超时、连接中断、确认的临时 5xx | 记 `upstream_transient`/`timeout` 与阶段。至多首次加两次重试，退避基数 2 s、上限 30 s，加有界抖动，服从共享配额、暂停、截止及可回溯性。超过次数或历史窗已不可取即保留缺口。DB 死锁/连接临时故障可限次重试本地事务，增加外部请求需重新通过完整准入。 |
| 429、明确访问频率限制、401/403、来源拒绝/验证码、证书/目标异常 | 记录脱敏原因，暂停适用来源或更窄已证实的产品范围，其他同范围 Job、手动和重试都受影响。`Retry-After` 若有效是最早可恢复时间，不自动放行。核实原因、额度、当前许可后由具名操作者恢复。保持登记身份和 TLS 校验。换 IP、伪造身份、规避验证码及禁用证书校验均为禁止操作。 |
| 重大结构漂移、错产品/错城、持续不兼容、越限、格式损坏 | 顶层类型/核心身份契约破坏或响应越限则隔离本次获取、记产品级固定原因并暂停该 profile。局部缺字段、错站或异常值只隔离可定位子项。已提交过的块和别的产品互不覆盖。规则恢复要有新契约版本和 F 回归。 |
| 200 合法空集合、只有旧发布或只有重复值 | 合法空值依各产品契约（如数组 `[]`）。无正文若未定义为空则是 `invalid_body`，C 缺核心身份的 `{}` 是形状错误。合法旧包/空包产生 `no_new`、读取时刻及缺口原因，不推进该窗最近观测锚。 |
| 暂停/撤权/无法补采 | 停止后续外部访问，停止排队中的有效提交。手动恢复需作用域、操作者、许可、配额和历史能力全部满足。重新触发同窗只针对剩余项，写明原因和前驱。允许核实的同产品同窗回溯（离线用 F 正反例），其他历史请求记 `backfill_unavailable`。 |

## 6. 单窗完整性与运行读端

**对账键和分母。** 读端按指定 WorkWindow 的目标清单联查本窗获准的 RunItem、Batch、Receipt。按产品、来源对象/站址期、指标、报告窗口/标准、源时标去重，再核当前修订和资格版本。三种数分别命名为“对象时槽数”“逐指标时槽数”“子项尝试数”。

| 输出 | 计算与缺口含义 |
|---|---|
| `E` 应到 | 由独立登记的发布节奏 × 所选目标标签 × 对象生效/覆盖区间和适用指标确定。保存依据、角标“全窗/实际覆盖子窗”与版本。对象集合、节奏或起讫不明时 `E=null`，只列已知目标和实际数，比例为 `null`。固定巡检频率、本次出现多少行、最新时刻均不能证明 E。已知产品没有该指标标 `not_applicable`，排除分母。 |
| `O` 实到 | 对象时槽有可归属且在目标范围的记录即计一次。逐指标另报“在该槽确实收到字段”的次数，显式 `null`、`NA`、删失及已归属的异常字段可计收到，缺键不计字段收到。失去身份/时间依据的行仅计异常尝试。不拿历史库里恰巧同刻的一行冒充本窗获取。 |
| `V` 有效 | 对每个指标时槽，在 O 内选当前、未争议、未退役、质量和单位/窗口合格且满足声明标准条件的版本。未知标准保留有出处的官方值，依赖已知版本的比较资格为空。重见相同有效值不增加 V。另列 `E−O`（未取得）与 `O−V`（已收到但达不到当前资格），原因可追溯。仅对 E 已知且大于零计算 O/E、V/E。E共/P、跨对象排名和统计解释由 S05 按同质输入计算。 |
| 裁决分类 | `first` 是本站首次写入该逻辑键，另报其中有效数及推进观测锚的时槽数。回补一个旧键也可为 `first`，判定源方新发布还需相应发布周期证据。`duplicate` 是规范内容重复，`watermark_advanced` 是同值且水位前移，`content_changed` 是可信修订，`late/retired_mapping` 保留既有状态。`same_version_conflict/unordered_conflict` 为争议隔离。质量待核、缺测、删失和格式异常另列，另以不同逻辑键核算新观测数。一次包/任务计数与这些行级数分开。 |
| 时效与变化 | `observed_at_utc` 为来源观测时刻，`fetched_at` 为 HTTP 实际读取完成，`requested/started/finished_at` 记录访问与执行。发布时间只在可信证据存在时记录。按产品/对象/指标求最晚观察和最近有效两个锚，用 PG 当前时间减观测时刻计算年龄。重复抓取只新增获准的访问事实。读端区分运行时认可的结果和现行资格/权利，后续争议或处置不能继续展示失效的 V。 |

**手工核算样例（F）。** S 的登记名册有两站，两站均覆盖一个目标小时，七项指标的窗口和标准已核。A 七项有效。B 五项有效、CO 显式 `null`、缺 SO₂ 键。对象时槽 `E=2,O=2`。逐指标共应到 14 格，收到 13 格、有效 12 格。CO 的 `E/O/V=2/2/1`，SO₂ 为 `2/1/1`。重复消息、两次 HTTP 或更多尝试均维持这些结果。换为无名册/节奏依据，E 与两类比率返回 `null`，仍能报告两站实到和对应字段状态。

**缺口归因。** `upstream_not_reported` 要有可核的源方未报/缺测说明或经核实的完整发布语义。网络中断、未调度或租约过期记 `not_acquired`。产品契约未提供记 `not_applicable`。键/值/时标/单位异常记 `invalid_field`/细分固定码。权限失效记 `permission_lost`。只有空包、旧包、清单不明或无法区分故障方时记 `insufficient_evidence`。`backfill_unavailable` 记录可补性，与缺口成因并列。已处置披露范围以当前许可为准。

**结果投影。** Run 报本次尝试，窗口只聚合一次有效认可。生命周期、传输结果、裁决增量、完整性（完整/部分/未知）和缺口原因分别投影。某次补采失败可以与此前窗口的部分成功同时存在。

| 运行结果 | 判据与优先关系 |
|---|---|
| 暂停/未授权 | 授权或来源/Job 暂停时优先标原因，窗口保留此前合法提交的事实及相应部分覆盖。 |
| 部分成功 | 有至少一格已成功提交且有效，同时还有未完成块、未到的应到格、字段异常、争议或达不到所需质量的格。已提交块后发生系统故障也记部分成功。响应内一项好、一项坏也可定位。 |
| 失败 | 无任何可接受的目标处理，访问、结构或事务失败。另列是否还可重试。 |
| 成功产生新观测 | 有目标新逻辑键且满足本次处理条件。另报新增有效数。E 未知时完整性仍为未知。 |
| 请求成功，未见新发布 | 合法空集合、只有旧时槽或同值复读，无新的目标键/修订。空窗缺口继续存在。 |
| 已处理修订/争议 | 仅发生版本推进/可信修订时单列 `changed`。已取得可归属响应但全部目标格争议、缺测或无效时记 `quality_only`、有效数 0。若另有有效格则按部分成功。 |
